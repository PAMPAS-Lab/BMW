# Video Studio 能力审视与迭代计划

适用：BMW，2026-10-04。当前功能、Schema 与权限以 [FUNCTIONAL_SPEC.md](FUNCTIONAL_SPEC.md) 为准；本文件描述能力判断和后续计划。标为“计划”的内容尚未实现，不提前写入当前功能说明。

## 总体判断与业务目标

Studio 已具备 Project 素材 → 分镜脚本 → 真实旁白 → 画面匹配 → 共享预览 → MP4 的原生制作闭环。当前提升重点转为真实取材、重点表达和讲解同步，优先服务以下任务：

| 任务 | 用户要完成的结果 | 优先补齐 |
|---|---|---|
| 网站交互录屏 | 把一次真实操作讲清楚，操作目标和结果可辨认 | 录制事件、可编辑焦点区间、点击强调 |
| 产品介绍 | 用真实页面状态证明功能，形成有节奏的讲述 | 操作片段、证据素材、品牌与版式模板 |
| 社交媒体素材收集 | 从指定帖子获得正文与素材，能够回溯引用 | 正文限定、来源记录、完整/截断/失败状态 |
| 课程与考题讲解 | 题目、推导、答案和验算随讲解逐步呈现 | 语音时间锚点、分步板书、独立答案校验 |
| 热点点评 | 把事实、来源和作者判断分别呈现 | 多来源证据、事件/发布时间、引用范围与更新提示 |

数字人是上述任务的可选出镜方式，排在基础能力之后。HyperFrames、Hypit 保留为场景编辑和内容/时间关系的主参考；BMW 延续自己的原生媒体实现。优先级为 **P0 录屏与焦点 → P0 来源与限定采集 → P0 中文语音锚点 → P1 讲题模板/动画 → P1 离线数字人片段**。

每轮保持 DSH 唯一 harness、`browser` 唯一模型工具、Project 媒体归属、草稿 ownerSessionId、revision 冲突保护、FIFO、取消与独立 Profile。计划中的字段与动作名称需在实现前定稿，不能由模型自行扩展权限。

## 当前能力与剩余缺口

| 环节 | 当前实现 | 仍需补齐 |
|---|---|---|
| 准备素材 | 文本/图像/音视频、笔记/大纲、零分镜草稿、Project 受限文本读取 | 一条帖子的正文、作者、日期与实际素材之间缺少结构化对应关系 |
| 分镜与脚本 | 全局/分镜脚本、增删排序、visualBrief、每分镜最多 12 条 sources URL | 句/词、引用、操作事件与画面重点尚无实测时间锚点 |
| 录屏与画面 | 页面录制/视频采集、截图/抽帧、取景/速度/起点、最多 8 段 cut/fade | 没有录制时的鼠标/点击数据与随时间调整的焦点区间；静态 crop 不等于自动缩放 |
| 旁白 | Edge/本地 Matcha、参数溯源、实测时长、stale 检测、narrate-pending 逐段续作 | Matcha 缓存仅提供合成；未实现可验证的中文句/词对齐 |
| 字幕与混音 | 独立字幕编辑、SRT/VTT、edited/estimated/mixed 来源、原声/旁白混音 | 估算字幕不能作为实测逐词时间；缺少同步板书与操作强调的通用锚点 |
| 图片与讲解 | 原生图片 inspect/annotate/draw、固定 Canvas 图形、独立 PNG 封面 | 静态板书可用，逐步揭示和知识动画仍需受限契约；不具备通用题库 OCR/解题正确率证据 |
| 编辑与交付 | 画布工作台、素材列表/图标/缩略图/预览、属性面板、顺序时间轴、封面与交付入口、撤销/重做 | 新能力应嵌入已有工作台；不扩展自由图层或通用 NLE |
| 检查与导出 | 只读 check、真实解码/覆盖/编码预检、H.264/AAC、Project JSON 验收报告、成片历史 | 提升表达质量与语义可追溯性，不能用可解码代替内容审片 |
| 成片复用 | 当前 render 按有效合成与源/输出/验收文件签名复用，forceRender 明确重做；封面/准备笔记不影响视频签名 | 已有整片复用不等于单场景缓存；本轮研究快照未验证后来加入的复用改动 |

既有 check/narrate-pending、图片解码预算、字幕导出、多段画面、Assistant 脚本/匹配入口、编码预检、会话归属、封面与交付能力保留。其覆盖范围见 [VERIFICATION.md](VERIFICATION.md)，不重新列为待开发项。

## 第一轮研究证据与边界

研究运行使用隔离源码快照、临时 Profile、独立 Project 与认证 Bridge，通过既有 browser 动作驱动原生媒体和 Studio。它是确定性脚本验证，没有运行真实 DSH 模型制作闭环。研究期间原项目发生同期源码更新；样片结果不能覆盖那些更新。

| 验证对象 | 取得的结果 | 未验证的范围 |
|---|---|---|
| 网站操作/产品介绍，52.48 秒 | 真实页面滚动、Studio/Timeline 链接点击，固定裁切聚焦正文 | 没有鼠标轨迹、自动焦点、点击/旁白精确同步 |
| 三来源资料点评，61.48 秒 | HyperFrames 页面画面与 Hypit/OpenScreen 中文摘要卡；原截图、全文和 URL 分开保留 | 不是当日热点新闻；没有证明跨平台采集、评论提取或事实核查质量 |
| 四步考题讲解，58.77 秒 | 自编 x²−5x+6=0，因式分解、根 2/3 和代入经 SymPy 独立校验 | 静态板书，不是 Manim 动画；仅一道题，无 OCR 或通用解题正确率结果 |
| 局部编辑与保护 | 改标题保留画面/旁白；旧 revision 被拒绝；改讲解词使旧旁白过期并阻止导出 | 没有单场景渲染缓存证据；当前整片复用需按最新源码另验 |
| 两条 B站公开页 | 未登录可观察标题、作者/日期、截图及图片候选；视频页显示试看限制 | 未下载完整视频，未验证评论；整页正文混入导航/推荐，媒体候选混入头像/缩略图 |

## 接下去的迭代计划

以下各轮均为待实施。按退出条件推进，不以未测算的日历工期作承诺。最小依赖为：录制事件先于自动焦点；真实声学证据先于自动时间锚点；来源记录先于可追溯热点点评；锚点先于讲题动画同步。当前首个开发范围是第 1 轮。

### 第 0 步：锁定当前基线

对最新源码确认 Studio 工作台与整片复用的现有覆盖：相同内容/文件不重编码，不增加 revision/exports；改字幕/音频/画面使复用失效；改封面/准备笔记仍可复用；forceRender 明确新制作；旧无签名输出可手动查看。记录源哈希和实际执行结果，不借研究快照证明当前实现。

复用既有测试与隔离 smoke，不重复开发已存在功能。该步完成后将研究网站样片作为第 1 轮前后对照基线。

### 第 1 轮 · P0：录屏事件与可编辑焦点

**交付物**：录制结果关联的 Project 事件记录；画面属性中的焦点区间编辑；共享预览/导出实现；升级网站操作/产品介绍样片。

先保存录制时钟与浏览器页面范围的点击、滚动/视口变化，记录相对时间、坐标域、DPR、视口及输出画面的映射。明确暂停、导航、缩放和截断的行为；记录上限和采样策略在契约中固定。只记录制作所需事件，不采集输入文本、密码、cookies 或系统全局键盘数据。Agent 动作与用户页面操作分开标明证据来源，不能由事后动作日志冒充实测光标轨迹。

先让用户手动添加/修改焦点起止、位置和缩放，再用确定性点击分组生成可编辑建议。在现有画面属性和顺序时间轴显示重点区间，沿用 revision/撤销；不扩展自由关键帧或轨道。没有事件的普通视频保留手动取景，自动建议明确不可用。

**退出条件**：

1. 一次包含三个实际任务步骤的录制，可回溯每个点击与结果；焦点不裁掉目标或操作结果，静止讲解可手动补重点。
2. 至少覆盖普通/高 DPR、页面滚动、视口变化与导航；抽样点击的事件时间与独立视频参照误差目标不超过 100ms。该值是待验收目标，不是已有测量结果。
3. 剪裁/改变播放率后重点仍映射到正确视频时间；改焦点不需重录、不使未改旁白过期；预览与导出在选定时间点比对通过。
4. 取消、关闭页面、过时 revision、Session/Project 切换及超预算均有明确结果；失败仅清理本次新产物，保留原录像。

**模块责任**：`browser-capability` 负责可信页面事件与动作准入；`media-native` 负责录制时钟、坐标映射与共享绘制；`feature-video` 负责草稿焦点数据、GUI、上下文与版本。不得引入 OpenScreen 自带 Agent 或第二个浏览器工具。

### 第 2 轮 · P0：正文限定采集与来源记录

**交付物**：Project 来源记录及素材/引用关联；准备阶段的来源详情、候选确认和正文范围选择；可回溯的资料点评样片。

先支持 B站公开视频/图文与普通网页，复用 selector 范围观察、截图、媒体发现、下载及视频采集。计划记录页面 URL、作者、发布时间、采集时间、正文范围/原文 Artifact、原始媒体 Artifact、引用片段与获取结果；未提供的作者/日期保持未知。网页正文、推荐列表、头像、封面和实际视频分开，人工确认候选后绑定。内容身份与获取记录可分别去重，不丢失多来源关系。

失败、需要登录、媒体候选、部分/试看获取、完整文件解码成功分别记录；无完整证据不得标“完整”。现有分镜 `sources` URL 可继续使用，不伪称已经存在完整来源 Schema。热点模板另记录事件时间与发表时间，事实引用和作者观点分开；采集日期不能代替新闻发生日期。

**退出条件**：

1. 复测研究中的两条 B站链接，并加一条普通网页和一个受控失败样例。正文素材不混入推荐/推广/头像；每条引用能返回对应原文、URL 和实际媒体范围。
2. 导航/取消/观察截断、缺失日期、重复素材、失效链接和试看得到明确状态；仅发现媒体 URL 不算下载成功。
3. 为至少三来源的点评输出可审阅引用清单，逐条检查关键事实的依据；来源冲突保留待确认标记，不由合成流程自动宣称事实核查通过。
4. 涉及平台完整视频时必须实际下载或采集并解码，报告是否截断；未登录失败不触发自动登录、cookie 导出或绕过限制。

**模块责任**：`browser-capability` 限定页面范围和观察状态；`platform`/`media-native` 按现有 Project 存储边界保存来源与素材；`feature-video` 管理引用关联和准备/分镜 UI。下载器适配单独评估，不向模型开放 shell。

### 第 3 轮 · P0：中文语音时间锚点

**交付物**：可追溯的句级对齐记录、人工校正与锚点引用；字幕、点击强调和板书揭示共享时间；通过证据门槛后才开放自动词/字级同步。

先比较可在固定环境运行的中文 ASR/强制对齐候选，记录固定模型、输入声道/采样率、原始输出、耗时和误差。现有 Matcha 不承担对齐；Hypit 仅参考证据归一化和确定性映射，Manim Voiceover 参考动画同步方式。证据不足时仍标估算/人工编辑，不换名冒充实测。低置信度位置可人工纠正，保存 script/audio 版本与时间域，废弃音频的锚点不得继续使用。

**退出条件**：

1. 至少 10 段真实中文音频，覆盖中英混读、数字、公式、停顿、补词/漏词；使用人工标注参照，输出每段误差而非只给平均值。
2. 句边界绝对误差 P95 目标 ≤250ms；若开放词/字级同步，明确中文分词/字符口径，边界 P95 目标 ≤200ms。阈值属于产品验收目标，候选不达标则保留句级/人工能力。
3. 修改一句讲解词只需重做受影响分镜旁白/锚点，未改分镜保持绑定；不承诺已存在句内音频拼接或单场景视频缓存。独立编辑字幕继续保留。
4. 锚点在剪裁、播放率和累计分镜时间映射后仍正确；GUI、browser、预览、导出、SRT/VTT 显示实际来源；对齐失败/取消不能覆盖人工校正。

**模块责任**：`media-native` 拥有固定对齐运行端口与声学证据；`feature-video` 拥有锚点、置信度、校正 UI 与 revision。模型仅提交受限请求，不接触本机执行或模型缓存路径。

### 第 4 轮 · P1：讲题模板与知识动画

**交付物**：题目/选项/步骤/验算模板、按锚点逐步揭示的原生板书、独立答案校验记录；必要时另做固定 Manim 运行器对照。

先用已有原生绘图完成静态与逐步板书，再评估公式、几何和函数动画的增量收益。固定模板和参数可进入受限宿主适配器，模型任意 Python/HTML 执行不进入 browser。题目识别、答案生成、独立校验和视觉呈现各自保留结果。

**退出条件**：至少 10 道自编/许可明确题目覆盖选择、代数计算与分步推导；每道都校验题面、答案和讲解步骤，失败题不得包装成已验证答案。至少一段含公式读法的讲解，其揭示节奏通过第 3 轮锚点验收；一道样题成功不外推到通用正确率。OCR 和复杂几何另设样本集与验收。

### 第 5 轮 · P1：可选离线数字人片段

**交付物**：审定音频 + 明确肖像输入 → Project 出镜视频的固定接口；可重复生成单段，保留真实 provider/模型/参数。

先测 MuseTalk/CosyVoice 候选的资源、安装体积、中文效果、代码/权重许可与耗时，再决定运行位置。本次 Darwin arm64 环境未配备候选文档所需 CUDA，模型推理尚无证据。先接独立或全屏片段；当前顺序 visualSegments 不能实现画中画。确需同屏时另定义最多一个出镜小窗的受限叠加契约，并验证遮挡和共享绘制，不先扩展通用图层。

**退出条件**：至少三段 15–30 秒中文出镜，人工核对发音、口型、边缘、字幕遮挡；记录耗时、失败/取消与复现参数。宿主资源或许可条件不满足时保留普通旁白视频，明确本轮数字人未通过，不假定可在本机免费运行。实时交互数字人不属于这一轮。

## 每轮共同验收与交付方式

- 实现前锁定输入/输出、字段上限、时间/坐标域、旧草稿兼容与模块责任；计划不自动成为现有能力。
- 每轮交付 GUI 与 browser 的同一受限能力、可编辑草稿、真实样片、来源/时间/媒体证据、实际测试结果，以及未覆盖事项。
- 按本次实际变更文件执行 `test:plan`、`test:affected`，完成 build/check 与所选契约/边界/真实 runtime 检查；新增/改名/删除测试运行 `docs:features`。更新 FUNCTIONAL_SPEC 的已实现部分及相应 VERIFICATION 证据。
