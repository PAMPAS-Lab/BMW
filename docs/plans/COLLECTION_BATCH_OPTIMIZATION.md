# 增量批量采集与有界并行

状态：设计先行，2026-10-22开始实施；实现与隔离回归已就绪，已登录主Profile的官方驱动九源验收由主Agent在当前视频任务收尾后协调。现有BMW与旧BMW定时计划继续暂停。本文不授权启用周期任务或迁移生产资料。

## 问题与衡量方式

同一轮九源的真实公开输入记录为：59分钟、231次browser调用、新增12条线索；原生工具执行约5分钟，工具之外的推理／输出／运行时等待约35分钟，来源间核对与接续空档约19分钟。这些分类不能进一步证明模型计算或网络延迟各自占比。九源固定为OpenAI公告、NVIDIA、Hugging Face、TechCrunch、量子位、X OpenAI、X趋势、YouTube OpenAI频道及YouTube AI搜索。

优化目标是用一个明确官方输入处理一批来源，令机械导航、原文读取、增量比较及状态汇总由确定的有界流程完成；Agent保留新闻相关性、证据归因、事件判断和异常处置。不能把减少材料／日期核验、跳过未读文章或把restricted当no-new计作提速。

## 不变量

- 模型仍只有BMW `browser`；官方驱动仍拥有Agent loop，Host不增加模型循环、额外工具、账号连接器、shell或任意宿主网络执行能力。
- 一批固定Project、Session、driver及既有原生恢复锚点；官方输入回执先于派发。unknown／uncertain从不自动再发。所有批量请求持有Host签发的批次租约，不接受网页生成的计划。
- 一个官方输入内部最多2–3个采集lane；不把多个Agent派往同一可变页面。每lane只控制其独立Agent页面，既有浏览器FIFO及Project过渡排他不放宽。
- 页面读取并行、sources和rolling的CAS提交串行；取消后等待全部lane真实清理，失败清理隔离，不提前放行用户任务。用户任务优先，批量支持和现有后台输入相同的让行。
- 不扩展事件put／merge／revise等Agent权限。可信GUI继续负责整理事件、策略、推荐快照与选题；不触碰旧草稿、配音、导出、采用账本或所有者。
- 部分／受限／失败不推进完成游标，已保存原文及未读URL继续保留。新页面日期取正文原始日期或显式可见time，不从列表日期／抓取时间推定。

## 数据与流程

新增独立追加型批次及检查点记录，不替换既有单源run格式。批次冻结来源ID、订阅revision、入口、绑定、72小时窗口、并发2或3、总页面／每源文章预算与deadline。每源保留入口原文获取、规范URL身份、已保存与未处理队列、访问状态、失败原因及摘要指标。旧来源／run／游标无需迁移；旧手动入口继续可用。

1. 可信界面一次勾选至多九个来源，创建一个批次并派发一个官方输入。先保存批次、子来源范围及uncertain状态；派发成功后登记唯一dispatch回执。并行度默认2，可显式选3。
2. 官方输入先调用一个批量采集browser动作。原生适配器读取固定入口的真实可见DOM并提取有界文章／帖子／视频链接；不读取凭据、页面内隐藏配置或执行正文指令。入口身份与原文SHA单独保存。
3. 按规范化URL去重及检查点比较；X/YT互动数变化不产生新的文章身份。固定文章范围内进入原文，保存正文、原始署名／日期（无法核实时null）和来源获取；每源预算与全批预算同时执行。首次基线也受相同预算限制；保留未读队列。
4. lane负责并行导航与读取。原文提交经一个串行提交器每次读取最新source revision后写入；结果再进入滚动账本。不同lane不能共享一个过期CAS，不递归等待自身BrowserKernel FIFO。
5. 返回一个有界结果：每源健康、变化数、未读数；每个新原文提供身份、元数据、精确短引文和缺口。Agent一次批量提交相关性判断与多条线索，不为每一条重复list/read/revision。批量提交逐项校验原文SHA、引用、平台ID和日期，保留明确的逐项回执；幂等提交不重复沉淀。
6. 成功完成所声明的入口／候选范围后才推进检查点。任一未读、部分或访问受限保留原完成游标与pending；检查点代表明确的有界页面范围，不能写作全站穷尽。之后GUI批量事件整理与推荐／制作单独进行。

## 浏览器与后台边界

并行位于一个已准入的browser批量动作内部，不能简单对`CollectionScheduler.enqueue`做Promise.all。现有AgentHost单活动输入、Project live run和主BrowserKernel FIFO保持。Host私有页面批量端口只接收闭合URL／SourceCollection范围与预算，内部使用隔离lane页面；批次租约在每次导航、读取和提交前后核验。渲染／录制／配音不进入该并行池。

后台scope显式允许自己的批次动作和子run，不泛化为任意项目或run。用户开始工作时沿现有background yield中止官方输入、取消lane、排空读写及页面销毁，再释放准入。重启只显示未完成／待核对状态，不能重投旧输入或自动恢复不确定批次。旧单源周期调度保持；批次能力经过实测后再显式接入配置，不自动启用任何计划。

## 九源适配与质量

每个固定源定义可见正文与链接范围及规范链接判据；文章页元数据沿现有SourceCollection选择器与验证。X趋势保存可审阅趋势入口原文，Agent可在一次submit中按原文保存相关词条观察，强制注明未确认事件并保持partial/旧游标；不能把词条自动写成已确认新闻；账号与YouTube频道／搜索逐条进入原始status/watch页面。缺日期的社媒保留线索缺口，不提升为合格推荐。登录、挑战、错误、空白和付费限制分别记录；不自动登录或绕过挑战。

结构化feed／官方API可作为将来的明确来源适配器，但本阶段九源对比仍使用同一配置入口与浏览器真实DOM，避免通过换样本声称同源提速。

## 分阶段实施与验收

### A：批次契约、增量检查点和提交

新增严格验证的batch／checkpoint存储、稳定URL去重、pending队列、批量线索提交与紧凑回执；旧单源契约兼容。测试取消／冲突／重复提交、缺日期、跨Project、订阅revision变化、partial不推进、旧记录保留及索引重建。

### B：2–3路页面执行和官方输入接入

新增Host私有有界页面池，在一个官方batch输入内执行，保留FIFO／Project过渡／用户让行／清理隔离。可信来源列表提供批次入口，单源入口保留；所有事件编辑权限不变。测试实际并发上限、慢lane、用户抢占全部lane清理、导航超时与清理失败、不确定回执和重启不重投、并行读取下串行source CAS。

### C：同九源基准与回归

先使用同九源URL／页面结构的确定性隔离夹具，以同一新服务的串行I/O作为受控基线，对比2／3路有界I/O；报告调用数、墙钟、原文／署名／日期质量指纹、缺口和pending。此基线不模拟旧Agent推理／输出与GUI接续耗时，历史231调用／59分钟只列独立参考，不能由夹具推算生产倍率。再用一次性Profile访问同九个公开入口，受限如实记录；其结果不等同已登录主Profile或付费模型覆盖。真实主Profile九源官方驱动比较由主agent在用户工作优先和视频编辑资源空闲时执行，沿明确绑定，定时任务仍暂停。

构建在/tmp隔离拷贝当前工作树进行，避免清除主agent正在使用的生成输出。依仓库要求顺序完成build/check/unit/boundaries、相关desktop／DSH／Studio／media／video／narration检查；运行范围与未验部分单列。新增测试运行docs:features；FUNCTIONAL_SPEC与架构／状态文档按最终实现同步。提速幅度只对实际同条件验证范围下结论，不预先承诺倍数。
