## 当前具体流程及失效点

1. 原站身份与日期核验 → 完整分发原片及原轨道归档 → SHA、时长、连续音视频包覆盖核对。此次约94分钟原片已经完成，保全约16分33秒；不是上传母版，也未连续观看全片。
2. 同一原片生成有哈希和时间映射的本地分段 → 原生ASR → 处理覆盖合并／边界补全 → 官方Agent基于全片转写核选题。全片转写已完成处理覆盖，但这不认证逐字正确。
3. 官方Agent读取发布稿、博客、源片区间 → 写五镜稿 → 准备图片／视频 → 配音 → 合成／导入Studio。此轮出现“先把稿和时长做成片，最后几镜靠照片／幻灯片加文字解释”的问题。
4. 导入产生新的草稿身份；旧稿引用没有自动迁移。引用曾留在旧806稿，新2fc稿是0条引用。导出技术校验仍能完成；来源存在和引用已绑定是两回事。
5. 对当前MP4取逐镜关键态、PCM、ASR → 内部独立审片 → 五镜／整片退回。初审发现后四镜约77%为静态主体，原声缺上下文、字幕断词、遮挡／裁切及长静音尾部。
6. 正常生产任务向当前2fc稿补3来源／6引用，替换素材、修改字幕及图层 → 已产生约40秒重导MP4，仍在进一步修改和取帧核对 → 最终当前MP4复核 → 再独立审片。当前运行仍在进行，不使用旧v1 MP4或旧审片结论交付。

根因是门槛错位：选题只证明有可用预览；技术 ready 只证明可处理；`visualBrief` 是文字计划；`.mp4` 与视频轨道并不证明真实运动；新稿不自动继承旧稿的来源引用。审核要求已经存在，但首次生产没有形成逐镜素材与证据齐备的可检查交接。

## 改为素材先行的首次制作

先写一句新闻主张和粗分镜，不先锁定全文／配音时长。选题可行性必须同时考虑新闻价值和画面可得性。

每镜交接至少包含：

| 项目 | 必须保存／核对的内容 |
| --- | --- |
| 编辑目的 | 这一镜新增的事实／原话／解释，观众看见什么具体动作及其与稿件的关系 |
| 事实证据 | 原始来源、公开日期及日期口径、精确引文跨度、事实／当事人主张／计划／推断分类 |
| 实际素材 | 当前Project artifactId、源哈希、原片时间区间及本地分段映射、可覆盖时长、裁切方案；不能只填 visualBrief |
| 动态核实 | 实际预览这一区间中的对象及动作；静态发布会幻灯片、照片推拉、无关机器人、旧新闻成片均不充数 |
| 原声 | 语义完整的实际说话区间、前指对象、中文译文、原声／旁白切换位置；保留必要上下文 |
| 布局与文字 | 手机画面主体、字幕／来源日期区域、需要的真实图解及其表达关系；英文产品名保持完整 |
| 缺口与替代 | 缺的是哪种证据／素材，优先同一原片的备选区间；不足就改角度或记未完成 |

执行顺序：

1. **素材准备**：一次定位全部镜头及备选，实际预览后再确定脚本；本批最后两镜须相关真实动态视频为主体。0–3秒必须连续合格实拍。正文也让真实拍摄／演示承担主体信息。
2. **稿与证据定稿**：按可用素材组织事实、完整原声与少量有据解释；每镜来源和引用在创建／导入当前稿时绑定，不留给审片补。
3. **制作前检查**：读取当前草稿实际主素材、图层及范围，确认开头和结尾，核查产品／合作方／31自由度和计划日期。新源码提供逐镜清单及配音／渲染准入，缺口未消除不执行制作；Host机械检查文件、引用、区间及声明绑定，动作／相关性／语义由官方Agent观察，Host不自动认证。当前生产实例保留既有代码，不中途部署。
4. **一次制作**：语义稳定后生成旁白，以实测音频调整剪辑／字幕；按语义分行、保留有理由的尾部停留，避免固定每镜秒数造成静音。兼容命令合并为一次有revision的事务，验证后保存；新的ID、生成结果和部分配音提交仍按依赖顺序处理。
5. **导出前验证**：结构检查和编辑者逐镜画面预检，明确剩余未核事项。先解决空引用、已知静态结尾、越界、失效旁白，不能让独立审片第一次发现这些基础缺口。
6. **导出与独立内审**：核当前MP4的所有逐镜关键态、未覆盖字幕、片尾进入／主态／退出，实际输出PCM与ASR；再由BMW官方运行时／模型独立逐镜和整片判断。新指纹必须重新审核；技术检查、模型结论和人工听感分开。
7. **局部返工**：按问题镜头和依赖影响修改，仅重配受影响音频；重新统一导出及复审。保留原稿、旧音频／旧MP4，不自动反复改写全部稿件。

这能让初审集中在真实的编辑判断和成片细节；模型仍可能判断错误、配音仍可能不自然，所以不能取消审片或承诺零返工。

## 部署与验证边界

当前机器人run3401仍有实际进展，本轮不构建清理工作区、不重启、不重复投递，不改生产Profile。源码在临时目录隔离编译／测试；当前BMW继续使用既有生成代码。逐镜清单、准入、批量转写及AAC修复已完成源码，不能冒称已在正在运行的生产任务生效。待生产和排队审片均真实结束并清理后按既有授权部署，不在两者之间抢重启窗口。

验证记录保存在 `outputs/gtc-berlin-three-news-2026-10-22/optimization-verification.json` 及相邻日志。204项相关单元／契约测试包括缺素材／引用、相同参考帧、音轨缺失、篡改／过期、所有权／CAS、取消保留、uncertain恢复和已完成续做；原生fixture使用独立临时Profile。Studio首次加载超时源于新共享契约使用浏览器无法解析的包名导入，已修复并实际复测通过；不把该失败略去。原生批转写使用已存测试语音完成实际分段、AAC归一化、本地base ASR、全范围覆盖与完成后续做无重复产物。付费模型、真实新闻首稿质量、94分钟新批次总耗时与人工听感仍未因此获得覆盖。
