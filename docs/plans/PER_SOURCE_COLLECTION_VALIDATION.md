## 采集结果和调度

- 每个订阅独立保存到期时间、失败计数及实际结果。某来源失败、受限或无进度，不能延迟其他到期来源。
- `partial` 不等于完整检查。已存原文和线索保留，旧游标不前推；有实际新增证据时按正常间隔继续，没有新增时只退避本来源。新增必须由已保存证据与投递前不可变基线比较，不能由模型声明、指标变化或重复子集判断。
- 有限周期中每个来源只处理一次，分别记录 completed/no-new/partial/restricted/failed。九源有限检查结束不等于九源都成功；仅完整检查且证据合格才能推进订阅游标。
- 重启沿原绑定和已保存轮次恢复。未知输入和未清理资源仍需核对，不能自动重发。旧计划的全局退避不应复制给无关来源。
- 通过本轮run的Host continuation复用上次 partial 的同订阅、同Session真实证据摘要，再继续尚未覆盖范围；不增加后台跨ID读取权限。当前未实现网页位置或全部 pending URL 的精确断点，不作此宣称。

## 实际验证

1. 先确认官方输入、工具、媒体、FIFO 和清理已结束，正常退出；顺序构建、检查及隔离回归后正常启动。保存独立新日志，不覆盖旧运行日志。
2. 沿已有九源计划、小时推荐任务和专用 Session 运行，不重复创建或重发旧输入。记录每源逻辑 run/dispatch、起止、实际清理、状态、游标前后、保存线索及独立 nextAt/failures。
3. 按正常到期或一次明确可信 GUI 验证输入运行候选整理，避免重复排队。BMW 产出最近72小时最多十个独立候选，给出处、日期、排序理由、素材与证据缺口。不足如实，报告与原生推荐预览/冻结快照分开。
4. 排队、执行、工具调用、错误及调用外耗时分开；没有同时制片窗口，不声称对制片无影响或真正并行。
