# 三类视频的文案与模板工作表

状态：设计样稿，未配音／未制作／未验收。与[制作方案](VIDEO_TYPES.md)共同使用；所有秒数是节拍目标，配音后必须按实测音长重排。方括号是必须用证据填充的槽位，不可作为成片文案原样输出。模板不绑定外部字体、素材服务或生成模型。

## 通用分段稿

每片先填：类型、主题、目标观众、观众已知什么、核心问题、看完应能回答什么、目标时长／比例、检索截止日、已核实材料、还缺什么、拟用模板版本。每段填写：

| 字段 | 填法 |
|---|---|
| 作用与一句话目标 | 例如“让观众区分命名表态与能力证据”，不用“展示一张图”代替沟通目的 |
| 旁白／保留原声 | 可直接朗读的完整句子；引用、译文、作者主张、编辑判断分别标明 |
| 证据 | source／acquisition／citation、论文图表或正文位置；已采用 artifact SHA、源区间／截图区域；缺失明确留空 |
| 画面与观察任务 | 主画面、辅助层、看哪里、何时揭示、何处停读；同时说明省略了什么 |
| 时间和声音 | 预估时段→实测旁白时长→有效句锚；原声／旁白／配乐的切换意图 |
| 验收与改稿 | 要问观众的问题、事实核对项、仍未知的条件；关联 scene/object ID 与当前 revision |

先选一个可辩护的主结论，再组织材料；正文不足以支持结论时改结论，不通过片头或音乐制造确定感。文字重点与旁白相互补充，避免屏幕堆满同时逐字读。

## T1：新闻速递写稿与版式

旁白起始选择使用现有 Qwen **闻怀之 `wenhuaizhi_v3.1`**、0% 语速，模型固定 `qwen-audio-3.1-tts-flash`。先按[设置与试听步骤](../../README.md#qwen-配置与试听)保存北京地域凭据并试听，再在视频默认设置或当前 Studio 草稿中明确选择；试听不会自动修改草稿。许言初、许玉远可作为备选，最终听感仍需实际生成与人工核听。此处是制作建议，TYPE-01 提供版本化方法和工作表，音色仍按显式参数／设置选取，也不将 T1 目标秒数当作配音实测时长。

### 两种引入，统一点评结构

| 配方 | 开场与证据 | 中段 | 收束 |
|---|---|---|---|
| N1 原声引入 | 本人片段＋身份／日期；保留能独立理解的一句原声，必要时译字幕 | 一句上下文→一个点评→一项理由或对照；原声结束后旁白接管，保持源时间连续 | “现有材料还不能说明什么／接下来观察什么” |
| N2 图文引入 | 原帖／报道整体定位→关键句局部阅读；保留作者和正文关系 | 同 N1；引文与点评用位置／标签区分，禁止把译文伪装原图文字 | 回到证据或观察点，保留简短来源标记 |

版式建议：人物／源图作为主画面，身份条只占必要空间；原文卡能单独停读，点评短句一次只强调一个词组；底部字幕、来源与原作者水印分区。默认深色中性底、白色正文、一个强调色；颜色不替代“原文／点评”标签。9:16 的宽截图要分段阅读，16:9 则重排为证据与点评并置，不机械裁切。

### SI 历史样片：45 秒候选稿

本稿只依据既有本机 SI 记录拟写，未重新访问帖子；制作前核对原帖全文、作者身份与上下文。SI 的具体展开含义如果来源未明确，不替作者补定义。任何短句都不应暗示今天发生。

| 目标时段 | 候选旁白 | 素材与画面 |
|---|---|---|
| 0–5 秒 | “马斯克想把 AI 改叫 SI。换个名字，技术就更强了吗？” | 原帖整体，短标题“改名 ≠ 能力证明”；这是编辑提问，不作为作者引文 |
| 5–13 秒 | “在这组旧帖里，他提出用 SI 替代 AI；随后又把 SpaceX 称为一家超级智能公司。” | 主帖 `2106665679361618173`，再到 `2106673377658413414`；关键句与译文分开 |
| 13–23 秒 | “先分清楚：这些材料记录的是他的表态，并没有在这里给出一组新的能力测试。” | 回到来源边界；用“已见：表态／未见：本组材料中的能力测试”，不能扩大为全网没有测试 |
| 23–38 秒 | “我的看法是，改名可以传达他想强调的方向，但不能替代能力证据。判断进展，更该看系统完成了什么任务、在什么条件下成功。” | 点评标签；原生简洁对照卡，不捏造跑分或任务成功视频 |
| 38–45 秒 | “所以，这条消息先当作一次表态。后面值得追的，是可核对的产品和测试。” | 回扣主帖，给出观察点；来源日期按核验结果显示 |

另一个开场候选：“从 AI 到 SI，马斯克这次改名，传递了什么？”两者先文字评审，选一版制作。此稿不保证配音恰好 45 秒；若超过 60 秒，先删减点评重复句，保留证据和限定，不靠全片倍速。保留旧 93.25 秒版用于比较信息取舍，短片另作独立目标验收，不能把时长减少本身计为质量改善。

## T2：综合科普写稿与版式

### 叙事配方 S1：现象→问题→机制→例子→边界

| 目标时段（四分钟示例） | 文案句式 | 画面配方 |
|---|---|---|
| 0–15 秒 | “你看到的是[现象]。关键问题是：[观众关心的问题]？” | 演示片段先让人观察，再标对象；不先讲一屏背景 |
| 15–40 秒 | “要理解它，先认识[最多两个必要概念]。这里的[词]指的是[具体对象／关系]。” | 原材料＋极简标注；整体定位后局部阅读 |
| 40–130 秒 | “先[步骤一]，这解决[障碍]；接着[步骤二]；如果[条件变化]，[结果／未知]。” | 同一原生流程图递进，穿插恰好支撑该步的实拍／UI／原图，保留对象一致性 |
| 130–195 秒 | “用这个例子检查刚才的解释：[输入]经过[过程]，得到[可观察结果]。与[对照]的区别是[同维度差异]。” | 例子或同条件比较；数值注明出处，不同条件不画成公平排名 |
| 195–240 秒 | “它能说明[范围]，还不能说明[边界]。回到开头，[一句回答]。” | 证据与示意回扣；源条目摘要与限制，避免全屏资料墙 |

S06 机器人样片的示例开场：“这段厨房演示里，机器人在完成一项任务。值得看的，不只是动作是否流畅，而是它经历了哪些步骤，哪些信息我们还不知道。”后续步骤名称必须从真实材料提取；不预写“自主规划”“理解意图”等尚未证实的内部能力。

至少三类材料各有职责，例如演示回答“发生什么”、来源图文回答“发布方怎样描述”、原生示意回答“如何把已知步骤连起来”。第三类是编辑解释，必须标明示意，不能伪装成内部系统结构。没有数据的片段不强加图表，没有来源的三维动画不作为机制证据。

### 视觉模板 S2：解释桌面

主区域可在演示、源文、图解之间切换，保留一致的对象名称和强调色；小章标题只显示当前问题，字幕区与示意标签分开。机制出现时先给全貌，再逐步揭示；每次转场传达“换证据／换阶段／作对照”之一，避免为追求丰富频繁切效果。人物、地图、档案、屏幕录制只在解释需要时进入。

## T3：学术解读写稿与版式

### 叙事配方 R1：问题→基线→贯穿例子→方法→证据→限制

| 目标时段（五分钟示例） | 文案句式 | 证据／辅助材料 |
|---|---|---|
| 0–20 秒 | “[论文／项目]想解决[具体困难]。作者提出[一句贡献]，我们重点看它怎样[核心机制]。” | 标题／版本／来源；贡献标为作者提出，不等于已独立证明 |
| 20–55 秒 | “原来的[明确基线]在[条件]下遇到[困难]。比较对象是[版本／方法]，不是所有旧方法。” | 论文引文、基线示意；未知比较条件先补齐 |
| 55–85 秒 | “用[小例子]走一遍：输入是[输入]，目标是[输出]。先记住[一个变量／状态]。” | 示例输入／输出并置；编辑构造例子明确标示，不冒充作者实验 |
| 85–185 秒 | “第一步[变化]，第二步[变化]，第三步[变化]。这一步与基线不同，因为[有依据的解释]。” | 原方法图→对应节点→受限动态重绘；变量／代码行同步，保留相同例子 |
| 185–255 秒 | “作者在[数据集／设置]报告[指标]。和[基线]相比[结果]；这张图支持的是[有限结论]。” | 原图／表编号、单位、样本与轴说明；重绘数据逐项可回查 |
| 255–300 秒 | “目前还有[限制]。代码[是否开放／版本]；我们[是否实际运行]。对[使用者]而言，可以先验证[具体条件]。” | 限制段、仓库位置与复现状态，回扣问题 |

A01 机制段示例句式：“先看这个例子里的四个阶段：TEXT、LATENT、TOOL，再回到 TEXT。每一步究竟改变了什么，要对照论文的方法定义；画面中的箭头只表示这里解释的流程，不能据此推断所有内部计算。”这是写稿方向，不是对论文机制已经核实的断言。正式稿须用论文定义替换泛称，并说明展示例子是否来自作者。

### 三种辅助模板

| 模板 | 具体设计 | 当前基础／需要的增量 |
|---|---|---|
| R2 原图精读 | 先显示图号和全图；依次框出相关部分，解释后回全貌；文字不盖图例和误差线 | 已实现阅读／聚焦／句绑定、TYPE-01 配方与明确来源映射 |
| R3 方法演进 | 固定输入、输出和节点位置；同一例子推进；只显示当前状态、下一步及必要解释 | 已实现 scienceState／关键帧和 AK-01 有界事件联动，按保留时钟派生 |
| R4 结果对照 | 数据／单位／条件在图旁固定；先说明横纵轴再揭示结果；作者报告与复现分列 | 已实现 AK-02 独立测量分组柱图、线性／对数散点；不能拿比例条替代 |

代码窗口只呈现实际引用的少量行并标仓库版本／位置；AK-04 已支持有界纯文本代码行高亮、聊天和有限父容器，不接受可执行富文本。复杂素材墙先判断主画面＋四路视频层是否足够，16 格可显式采用 AK-03 分块预合成；同时解码预算保持不变。

## 改稿与交付工作表

每轮保存“原句→改句→理由→依据→受影响对象→重新检查项”。只改 T1 结尾点评时，原声引入及其来源保持；T2 更换某步素材要检查图解与解说是否仍对应；T3 改论文版本或数据要使相关主张、图表、旁白与审阅一起进入待核对。不能仅更新来源标签就认定整片有效。

交付时分别填写技术检查、Agent 内容意见、人工试听、目标观众复述、最终采用版本。没有做的检查写未执行；发布或对外声称“支持三类视频”以前，至少满足[主方案考核](VIDEO_TYPES.md#考核设计与退出条件)。
