# 三类视频制作与考核方案

状态：2026-10-17 需求更新／方案设计，**尚未实现**。本轮只更新文档，不创建样片、不修改代码或现有 Project。用户确定的下一阶段考核是新闻速递、综合科普、学术解读三类视频；新闻速递为 30–60 秒，其余时长与评分门槛是本方案建议，待样片验证调整。全局实施顺序见 [NEXT_STEPS](NEXT_STEPS.md)，可直接用于写稿的工作表及示例见[文案与模板](VIDEO_TYPE_TEMPLATES.md)。

## 目标：一种制作流程，三种内容要求

考核对象是 BMW 能否帮助官方 Agent 用真实材料完成可理解、可修改、可追溯的成片。每类不仅提供一套颜色或片头，还需要写稿结构、证据要求、素材角色、镜头配方和验收标准。类型是创作起点，允许删减和替换，不强制每片填满相同段落。

| 维度 | T1 知名 IP 新闻速递 | T2 综合科普／量子位类 | T3 学术解读／AK 类 |
|---|---|---|---|
| 观众任务 | 迅速知道发生什么、为什么值得注意、点评依据 | 理解一个问题、机制或过程，并能解释一个具体例子 | 理解论文／项目解决什么、新方法如何工作、实验能证明到哪里 |
| 核心组织 | 一件事＋一段证据＋一个点评 | 一个主问题＋分步解释＋多种互补材料 | 一个研究问题＋基线＋方法＋结果＋限制 |
| 时长 | **30–60 秒**；首片按 45 秒设计 | 建议 3–5 分钟，必要时 2–8 分钟 | 建议 3–6 分钟；另可做 60–90 秒导读，不替代完整机制考核 |
| 脚本密度 | 不堆新闻列表，不加人物生平 | 先具体现象再解释术语，章节之间有因果或问题承接 | 先给直觉再给变量和步骤，逐项比较条件 |
| 主材料 | 当事人片段或原帖／报道截图；补充上下文 | 原始演示、图文、档案、图解、必要的实拍或 UI 素材 | 论文图表、方法图、项目文档、代码／演示、实验条件 |
| 视觉任务 | 定位身份→读一句证据→区分事实与点评 | 让不同材料各回答一个问题，图解贯穿解释 | 原图整体→局部→受限重绘→回到实验／原图核对 |
| 原声 | 短引入可保留原声，再明确切入旁白；图文版不伪造原声 | 演示保留必要声音，其余旁白与配乐有明确分工 | 原演示声和讲解分开，不能用 ASR 当核听 |
| 默认构图建议 | 9:16，人物／主图与短证据卡、点评字幕分区 | 16:9 解释版；需要竖版时重新编排阅读窗 | 16:9 优先保证图表、公式和代码可读；竖版另做局部叙事 |
| 首轮样片 | 既有 Musk SI 重剪 | 量子位 S06 机器人任务主题的独立科普编排 | AK A01 TEXT→LATENT→TOOL→TEXT 机制段扩展为学术解释 |

T2/T3 时长建议均服从现有 720 秒／96 镜头等预算；模板不能提高上限。选定样本若缺必要材料，先缩小讲解问题或显式换题，不能填造论文结论、演示帧或未经执行的实验。

## T1：证据先出现，点评只讲一个判断

建议 45 秒骨架：0–5 秒身份和事实钩子，5–13 秒关键原声／原文，13–23 秒最小上下文，23–38 秒点评及理由，38–45 秒边界与观察点。原视频引入可在前两段合并；图文引入则保留作者、日期和正文可读区域，避免用装饰头像代替来源。

点评必须能指回事实，明确区分“当事人说”“材料显示”“我们的判断”。不凭一个标题宣布产品已发布、技术已实现，也不把反讽、转帖和本人发言混在一起。结尾给一个可观察后续信号，不强制口号或互动引导。中文稿先按自然语速起草，再用实际旁白时长缩改；不能靠持续加速塞进一分钟。

Musk SI 基准为历史 Project `b5604740-9ef4-4461-9608-f83c6ef9ead7` 的《马斯克要把AI改叫SI》，草稿 `2d0e9f1c-79a4-4074-b050-04996df58ffb` revision 64，最近登记导出 revision 63、93.25 秒。另一稿《AI改名SI：Trump引爆的命名链路》约 111.54 秒，只作为旁支材料，不默认采纳标题里的因果判断。这两稿都不是 Musk daily。原文件是旧版草稿结构；后续制作先按显式迁移流程验证副本，或在当前格式中新建并采用已核验素材，正常启动不自动迁移，原稿原片保留。

改进重点：从多帖串讲收敛为“改名措辞是否代表能力进展”一个问题，主证据保留原帖，删除不能支撑判断的围观反应和冗长命名史。文案示例是历史样片脚本，不把 10 月初记录当今天新闻；源文与上下文须在制作前重新核对。先交一份 45 秒稿和两个开场文字候选，选定后再制作一版；不自动生成多份完整成片浪费资源。

## T2：多种材料共同解释一个问题

建议四分钟骨架：现象与问题 15 秒、对象和必要背景 25 秒、机制分三步 90 秒、例子或对照 65 秒、限制与回答 45 秒。各段可合并；不是每隔固定秒数强行切素材。

先写“看完能回答什么”，再建立材料角色表：实拍／演示展示现象，原文支持事实，图解解释关系，图表展示测量，类比辅助直觉。每段至少有一个可指认的视觉任务，例如“看手先移到哪里”“比较同一条件下两条路径”。不要求形式种类越多越好；首轮验收至少三种有必要作用的材料，避免素材轮播代替解释。

S06 首轮可围绕“机器人完成厨房任务，演示展示了哪些步骤、还有哪些条件未知”组织，采用原演示、来源图文和 BMW 原生流程图；示意图只表达可证实的过程。先补齐来源及演示条件，未知处直接标明；不能从成片点云画面推断编辑器或机器人具体算法。之后用 S09/S10 的长篇／数值题材做迁移验证，不把旧完整成片重新导入后称作 BMW 独立制作。

## T3：围绕机制与证据组织辅助材料

建议五分钟骨架：问题与贡献 20 秒、基线与困难 35 秒、一个贯穿的例子 30 秒、方法三步 100 秒、实验与对照 70 秒、限制及复现入口 45 秒。复杂论文可只选一个贡献深入讲，不照搬摘要章节顺序。

材料入口以论文题目／作者／版本、项目仓库及版本为锚；帖子是发现入口，演示不是论文全文。建立贡献清单与证据对应：论文原文、图／表编号、实验设定、演示区间或仓库位置。作者主张、已报告结果、独立复现、编辑推断四种身份分开，未运行仓库不写“已复现”。“最新”要注明检索截止时间，不凭帖子时间认定论文版本。

模板应支持一个例子贯穿输入、状态变化、工具调用、输出；公式先说明变量和用途，代码只选解释所需行。科研图表必须保留基线、单位、数据集、比较条件和作者报告范围，统计不确定性有则保留，无则不能补画。原图裁切或重绘须能回到原出处，重绘不冒充实验截图。

A01 首轮优先做 20–30 秒机制关键段和一张结果图的可读性验证，再组装全片；具体贡献、数字和术语必须从论文／仓库核实，AK 视频本身不能替代这一环。AK-01 事件联动和 AK-02 图表按样片需要启用；16 格素材墙、外部三维生成不是所有学术解读的必选前置。

## BMW 制作便利：从模板选择到改稿

提出新计划 ID **TYPE-01 类型制作支持**，作为 CONTENT-01／02／07 的产品化入口，不另建执行引擎。用户可说“做一条新闻速递”或在 Studio 选择类型，补充主题、受众、来源、目标时长与比例；已有信息自动填入候选，不反复询问。缺事实时显示具体缺口与可用替代路径。官方 Agent 负责研究和写作，BMW Host 负责类型契约、资源、状态、界面和确定性检查。

| 制作阶段 | 用户／Agent 得到的便利 | 确定性检查和边界 |
|---|---|---|
| 选类型与任务 | 类型卡显示适合题材、结构、推荐时长、输入示例；可定制 | 类型不改变权限／预算；T1 30–60 秒是该考核约束，T2/T3 建议可改 |
| 备资料 | 按“引入、事实、机制、结果、限制”组织已有 Project 素材；标缺来源／区间 | 素材身份、哈希、归属可验；材料是否充分仍由 Agent 与人判断 |
| 写稿 | 分段工作表，旁白与画面并排；每段写一句学习／观看任务 | 区分事实、引用、推断；引用存在不等于事实已认证 |
| 配模板 | 按角色推荐可用的原生卡片、阅读、图解、片段，而非暴露几十种效果让 Agent 猜 | 只返回当前有效目录中可用能力；不支持时提供真实降级方案，不静默删内容 |
| 排时间 | 初稿预估；配音后依据实际音长、停读和源区间调整 | 只有一套权威时间线；估时、编辑句锚、ASR 和声学证据分别标注 |
| 检查与审片 | 技术问题、内容检查项、人工反馈分列；跳转到具体镜头／来源 | 显示当前 revision／成片指纹，过期检查失效，不把自动检查写成用户认可 |
| 改稿 | 说明受影响的来源、旁白、句绑定、镜头与成片；可保留无关材料 | 复用 CONTENT-04／05，GUI 改动不被模板重新套用覆盖，旧导出保留 |

### 三层模板契约

1. **类型指导**：受众、问题、叙事槽位、证据要求和评审量表。是版本化数据与方法，不是新增系统权限或任意外部 skill。
2. **段落配方**：把“原文引入”“机制三步”“实验对照”等槽位映射到现有文档对象和有限编辑命令，形成可预览的变更提案。首次创建可应用；已有草稿重新套用须显示保留／替换列表，并经明确采用，不能整片重置。
3. **视觉模板**：版式、字体层级、配色、字幕安全区、源文阅读窗与图解样式。已有卡片和共享 painter 优先；只有样片证明缺少表达才增加原生组件。比例变化要重排证据区域，不对整个画布简单缩放裁切。

每个类型／配方保存稳定 ID、版本、适用条件、输入槽位、必要能力、默认值、预算及检查项。原生 palette 可给合理默认，但正文／引文／点评／数据／限制必须有一致视觉区分，不能只靠颜色传达身份。设计草案用 `news-brief`、`science-explainer`、`research-explainer` 作类型名称，**这些不是已发布的 Schema 枚举或动作名**。

### 数据、状态和模块落点

方案验证阶段使用现有 preparation.notes／outline（规范文档投影为 content.brief）保存工作表，不往 2.9 文档塞未支持字段。产品化时才定义类型化创作简报与段落映射：profileId/version、受众／问题／时长意图、claim 与 source/citation 关联、素材角色、稳定 scene/object ID、模板应用记录、评审结果。字段是候选，不提前指定下一个文档版本。

故事结构只保存语义角色和对现有对象的引用，实际秒数继续由当前 timeline／音频证据管理。多配方实例不能复制独立时间线；对象删除、换素材、改旁白后按依赖标记失效。已采用的模板版本固定，目录更新只给可审阅迁移提案，不后台覆盖用户编辑。

显示“资料待补→稿件待审→可制作→成片待审→已验收”等制作视图，但状态从当前 revision 的证据与检查派生；技术可制作与内容验收分别显示。旧人工结论可追溯但不能沿用到新成片。语义审稿由官方 Agent 给出建议，不能由 Host 执行模型循环，也不能用关键词规则伪称已验证科学结论。

| 层 | 候选职责 | 复用基础 |
|---|---|---|
| feature-video | 类型目录、简报验证、配方解析、提案／采用、依赖检查、类型审阅表 | studio-discovery、video-edit-contract、studio-sources、studio-materials、readiness、export-review |
| media-native | 现有卡片／阅读／图解绘制；必要的图表或事件状态增量 | card-templates、science-spec、共享 painter、composition-quality |
| browser-capability | 经验证的有界目录发现、工作表读取与提案采用能力 | 唯一 browser 的闭合动作目录、可信上下文，不暴露 shell／任意文件／HTML |
| BMW UI／官方驱动 | UI 展示类型和分段稿、缺口与变更预览；官方 Agent 自主使用目录完成任务 | BMW 统一会话 UI，各 harness 自己的 Agent loop |

所有读写沿用 Project／Session 归属、expectedRevision、FIFO、Project 切换排除、取消等待实际 worker 清理及失败隔离；不新增跨 Project 素材可见性。只读提案有界分页且携带基准 revision，采用时重新验证能力、素材和冲突，过期提案拒绝。模板不能触发不确定输入自动重放。

## 考核设计与退出条件

首轮每类一条主样片；随后每类换一个主题复用同一已冻结模板，证明不是为一条视频硬编码。样片制作由 BMW 官方 Agent 和原生动作完成，记录模型／驱动、模板版本、人工指导和外部材料；不得用开发侧代写最终稿、脚本合成或整体导入参考成片冒充制作能力。不同驱动结果分别记录，不用不等条件比较给模型排名。

技术准入必须先通过：无丢素材／越界、导出可解码、字幕和核心证据在目标屏幕可读、来源区间及图表条件可追溯、改稿后时序有效、取消和冲突行为正确。T1 成片必须 30–60 秒；T2/T3 在各自约定时长范围。模型未接收音频时模型核听仍为未执行；安排人实际试听并记录，未核听就保持音频验收待完成。

建议内容评分各项 0–4：0 缺失／错误，1 严重不足，2 部分达成，3 达成，4 清楚且有效；各类五项总分 20，首轮建议达到 16 且无单项低于 2，关键事实误归属／伪造结果直接不通过。该门槛是拟定考核标准，不是已经测得的质量分数。

| 类型 | 五项内容维度 | 观众复述问题 |
|---|---|---|
| T1 | 事实与身份、引入速度、点评依据、压缩与停读、结尾边界 | 谁做／说了什么？哪些是事实、哪些是点评？ |
| T2 | 问题主线、分步解释、素材互补、概念准确、例子与边界 | 核心过程如何发生？换一个条件会怎样？若无法预测，能说明哪里未知？ |
| T3 | 贡献与基线、机制可理解性、图表条件、证据归属、限制与复现状态 | 相对什么改进？机制走过哪几步？实验尚不能证明什么？ |

每类建议至少三名目标受众，T1/T2 以非专业观众为主，T3 有基本相关知识但未读该文；记录逐人回答及具体时间点误解，小样本仅作修订依据。另有领域核对者检查科学主张，Agent 自评不能代填用户／专家反馈。无法取得反馈时技术状态可通过，内容状态保留待验收。

交付清单：任务简报、完整稿与变更理由、分镜／素材角色表、来源与主张对应、采用的模板版本、实际音长与成片、关键帧／手机阅读检查、用户反馈和修订记录。先在 Project 内形成完整交付，便携工程包 DELIVERY-01 可后续增强，不阻塞第一批样片。

## 分阶段实施建议（另行安排开发）

- **阶段 A：冻结三类要求与过程模板。** 本轮文档交付；未来先补 SI 源材料核验，确认 T2/T3 主题和目标受众。无代码完成声明。
- **阶段 B：用现有能力制作三类基准片。** SI 先做 45 秒，T2/T3 先验机制关键段再全片；记录便利缺口与表达阻塞。不能支持的图表先保留可读原图并标局限，不虚报新组件可用。
- **阶段 C：实现 TYPE-01 和最小支持。** 固定版本类型目录、分段工作表、配方提案／采用及审阅表；SOURCE-01、CONTENT-04／05 取实际需要的最小切片；AK-01／02 仅按 T3 阻塞项推进。
- **阶段 D：复用与回归。** 每类新主题一条，不改模板内核就能完成；测试编辑冲突、过期引用、变更失效、比例重排、超预算、取消清理，再内容验收。AK-03／04／05、下载恢复、交付包按真实需要展开。

本轮不改变 FUNCTIONAL_SPEC 的能力声明。后续每项实现后更新权威规范、Schema／动作发现和测试映射；新增测试运行 docs:features。构建串行，按 AGENTS 执行 build、check、unit、boundaries 及相关 DSH／desktop／Studio／media／video／narration 验证，全部使用一次性数据。现有通过只能证明已实现基础，不证明三类制作支持或内容考核已通过。
