# 可编辑交付与有界获取增量设计

状态：2026-10-17 设计，尚未实施。来自[本机审计](../research/LOCAL_RECORDS_AUDIT.md)，统一排序见 [NEXT_STEPS.md](NEXT_STEPS.md)。已经修复的 Referer、源时钟、原声切旁白、长篇及卡片能力不重新列为功能缺口。

## DELIVERY-01：可编辑交付包

先在 feature-video 定义闭合的原生导出请求：可信 Project／Session、draftId、expectedRevision、明确素材范围。输出规范化视频文档、素材清单及 SHA、字幕／引用、实际成片 revision 和检查回执；打包由有界原生资源层执行，输出 Project artifact。现有 read-document 或开发侧复制目录不是该能力。

导出前快照 revision，逐项验证 owner、来源和素材存在性；任一必要素材缺失则明确失败，不静默生成“可完整恢复”包。限制单包字节数／素材数，最终数值须按资源测试确定；路径使用内部映射，不包含绝对宿主路径、浏览器数据、凭据、Agent 对话或无关 Project 资源。导出后校验清单和内容哈希。

沿用 FIFO、Project 切换排除与取消清理，失败残留资源按现有隔离规则处理。首期不承诺跨版本导入、完整撤销历史或包含无法授权再分发的来源文件；被排除素材须在清单标明，不能称自包含。测试覆盖 revision 竞争、跨 Project、缺素材、超预算、取消／清理失败，以及文档与成片版本不同。候选新 browser action 仅经闭合 Schema 和目录准入后发布。

## MEDIA-04：有界下载恢复

现有来源头修复和完整文件下载已完成。增量是在 Host 管理的原生获取任务中保存来源页面、确认的媒体身份、任务状态与字节预算；Agent 只能通过受限动作读取／取消，不能提供任意 header、cookie、宿主路径或网络脚本。

分两步：先做有界队列、取消及过期链接重新确认，随后评估条件 Range 恢复。刷新必须重新从已授权页面确认同一媒体；ETag／Last-Modified、长度与响应范围不一致时丢弃部分内容，重新完整获取或明确失败，不拼接不同版本。跨源重定向继续剥离敏感头，遵循已有来源策略；不自动无限重试、不重放不确定模型输入。

保持 512 MiB 文件和 1800 秒原生处理边界；S04 无低清版本仍明确不可用。测试使用一次性本地 HTTP／Electron fixture：URL 过期、身份改变、206／200 分支、Range 不支持、资源超限、断流、取消、Project 切换与清理隔离。真实平台策略与登录行为另列外部验收，离线通过不能替代。

## SOURCE-01 补充验收与历史回归

在既有 SOURCE-01 设计中区分作品、原帖、引用／转发、传播帖、作者提示词回复和媒体版本；关系必须有证据，未知可保存，不按文件名猜测。用 Musk 身份混淆、Pelican 引用时间与模板线索、量子位 S10/S12 缺独立链接做拒绝猜测的用例。

在后续相关运行时改动时补首视频 PTS 大于零的 Ready／渲染一致性夹具，并确保画面 gapSeconds 不被解释为音频静音。这是定向验证需求，不宣称当前已复现旧故障。每个增量按仓库完整验证要求执行，完成后更新 FUNCTIONAL_SPEC 和测试生成目录，再归档；本文不是实现完成回执。
