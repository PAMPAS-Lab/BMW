# 素材库、项目专题与全局关注方向

状态：六阶段已实现并通过隔离验证。本文描述目标；当前已实现能力以 `docs/FUNCTIONAL_SPEC.md` 为准。

## 使用场景

### 项目内探索、采集与制作

用户在当前 Project 建立轻量专题，提出问题、搜索、保存证据、整理和制作。保存的 source/acquisition/artifact 始终属于该 Project，并自动进入全局素材库聚合视图，不额外复制文件。专题可以关联多份材料和多个作品；没有入选或采用的资料继续保留。作品以明确的成品身份、版本、Project 和采用关系进入素材库。临时专题不要求订阅、定时任务或关注方向。

### 专题升级为全局长期方向

用户可把项目专题提升为全局方向，也可在素材库直接创建方向。方向有独立稳定身份，聚合多个 Project 的专题、事件、资料和作品。提升只建立关联并复用用户确认的研究要求，不移动历史文件、不改写原始 Project。方向配置采集保存 Project；后续可在其他制作 Project 中选题并复制完整证据。归档或失效的采集 Project/Session/driver 暂停运行，不能静默改绑。

## 对象与归属

| 对象 | 内容和归属 |
| --- | --- |
| Project | 页面、会话、来源、媒体、草稿和作品的资源所有者 |
| 项目专题 Topic | Project 内的研究问题、说明、标签、状态；跨 Session 持久化 |
| 全局方向 Direction | Profile 内的长期主题、标签、采集目标 Project、主题关联及启停状态 |
| 来源订阅 Subscription | 所属方向、固定入口、身份依据、主题/地区/语言、备用入口、游标与健康状态 |
| 线索 Lead | 可核验的平台 ID/URL、发现时间、来源及缺口，不冒充已保存原文 |
| 事件 Event | 主体与变化、原始时间精度、关联证据、独立修订和演进关系 |
| 材料 Material | 现有 source/acquisition/artifact 身份和 SHA；不因关联方向而复制 |
| 推荐 Recommendation | 策略版本、截止时间、事件修订和证据指纹的稳定批次快照 |
| 作品 Work/Export | 草稿身份、真实导出版本/指纹、成品用途和独立验收状态 |
| 关系 Relation | 属于专题/方向、参考、计划使用、实际采用、派生和复制关系 |

Project 与方向不是一一对应；一个 Project 有多个专题，一个专题可关联多个方向。标签描述内容，结构化 ID 表达归属和采用。全局聚合可展示跨 Project 摘要与关系；Agent 跨 Project 读取正文或媒体仍须先复制完整证据到活动 Project。全局配置写入必须经可信 GUI；Agent 不能自动提升专题、启用长期收集或改绑采集目标。

## 材料与作品

用途与媒体类型分开：来源素材、加工素材、预览/中间版本、成品、辅助记录。成品可以是视频、图片、音频或文字。旧文件仅做只读兼容投影，不根据文件名冒认正式成品；有明确实际导出记录时才能投影为成品。用户可显式分类。导出不代表人工验收。

关系区分 reference（参考）、planned（计划使用）、used（实际采用）、derived（派生）、copy（复制）。采用记录绑定作品输出版本、材料 SHA 和可选源区间；参考列表不等于实际采用。视频导出根据实际导出时间线和输出指纹保存，后续改稿不覆盖旧导出关系。其他作品由实际制作工具或用户明确登记。跨 Project 副本保留原身份溯源，同时属于目标 Project。

## 滚动采集与事件流

流程：方向配置 → 固定来源巡检/主题搜索/社媒线索 → 保存证据 → 归并事件 → 补充重点媒体 → 推荐快照 → 用户选题 → 制作。

原始资料入库不受十条或72小时限制。证据状态、媒体状态和使用状态分别保存；线索、完整原文、已核对日期、真实短预览不能互相冒充。旧闻与历史背景保留；新进展形成事件修订。确定性 ID/URL/SHA 去重由 Host 执行，语义合并由官方 Agent 提议，保留依据及拆分能力。

X 使用固定原创账号、主题搜索和明确地区的趋势入口；YouTube 使用核验频道、主题/日期搜索、原始采访和演示。趋势记录必须带观察时间、地区/语言/入口和可见指标；没有连续观察不能声称增长。热度首次发现、原始发布、录制、更新和采集时间分别保存。

每次有限任务先读取游标，广泛检查新增，再集中获取重点素材。来源分别记录检查成功、无新增、部分完成、访问受限和失败，不能把空回包视为无新闻。提交证据后推进游标；按稳定操作 ID 幂等保存，失败保留已提交项。取消等待真实浏览器/原生任务清理，清理失败隔离。

## 推荐与制作兼容

AI 新闻默认近72小时，完整推荐批次为十个独立合格事件。不足时展示准备数量/原因，可继续补采或由用户明确接受较少项；不得凑旧闻或伪造证据。研究过程可以分批保存。其他方向可用周窗口、专题相关性等不同策略。

推荐快照绑定事件修订、证据、策略版本、生成截止时间及理由，后台更新不会重排已展示卡片。选择时重核时效和证据。已选择草稿固定引用版本，后台不得替换素材或覆盖 GUI 编辑。看过/排除/已制作状态注明 Project、方向或批次范围。

现有 `video-studio/news` version1、Project/Session、旧三题/十题批次、草稿 ID、dispatch ready/uncertain/sent/failed 全部保留。新增对象与旧记录关联，不重置或移动旧文件；现有 `library.news` 和 `video.studio` 研究/可信用户选题/制作入口继续工作。独立采集整理与推荐等待选择门禁后续分离，不能借此解除制作限制。

## 运行与权限

只有 `browser` 一个模型工具；新增能力为闭合、分页、CAS 的 library 动作。官方驱动拥有 Agent loop，Host 只管理数据、输入收据、任务调度和资源准入。全局方向不拥有无限后台循环。周期运行绑定明确 Project/Session/driver，复用现有队列和 Project-transition exclusion，避让用户操作；不确定输入不自动重投。应用关闭不承诺采集，恢复后执行有界重叠补采，不无限补跑。

## 存储与检索

新增项目数据放 `Project/library/`，全局方向放 Host 选择的 Profile 元数据目录。每个存储闭合版本化、限制大小、CAS 原子保存、验证真实目录/普通文件/链接与身份；损坏保留原件并报告，只有缺失才能初始化。不同 Session 共享 Project 专题，Project 切换不接受过期回包。

第一阶段添加小规模有界专题和方向，不改变原始来源存储预算。长期采集启用前，必须完成 Project 内来源/事件分片和可重建增量检索：现有200来源/1000获取、200媒体索引和16MiB检索预算不能直接当长期容量。使用稳定 ID 和旧路径兼容读取，不能简单放大 JSON 或以无限新建用户 Project 规避容量。原文与事件默认保留，媒体按预算分层保存，作品引用的证据受保护；自动清理需另有明确产品规则。

## 界面

Project 内提供专题列表、关联材料/作品、关联方向和“设为长期关注”。全局素材库提供全部资料、成品、项目专题、关注方向、滚动事件、本次推荐和来源/采集健康。方向聚合一事件一卡，多份证据展开；区分最新发布/发现/进展。选择资料或事件后指定制作 Project，复用完整证据复制和 Studio 交接。

## 第二阶段实施细化

独立 Project/library/exports 版本1账本记录实际成功导出的作品身份、Session/草稿及其导出revision、原生渲染版本、合成快照SHA、输出SHA、素材SHA、实际启用的主画面/原声/旁白/卡片图片/独立图层和音轨的文件时钟区间与输出区间。静音、隐藏、整段透明、准备清单和仅参考内容不记实际采用；末帧停留与原声到源终点的截断分别记录。区间表示合成器输入时间线的采用，不证明遮挡后的每个像素或人工核听。保留来源获取身份和已验证跨Project复制溯源；录屏原片区间仅作采集范围说明，不把非线性录制时钟伪装成精确原片映射。

每次真实导出一条独立记录，缓存复用不新增版本。记录在草稿提交前暂存，草稿成功后提交；崩溃留下的暂存只有在原草稿存在匹配的导出回执时才可读取为已完成。已提交版本不受草稿最近30条导出窗口或草稿后续编辑/删除影响。旧文档只读投影已有导出回执，采用详情标未知，不用当前时间线回填。损坏记录保留，单条错误不隐藏其他资料。账本失败不撤销已成功的原制作流程，但返回并显示明确警告，不能声称采用已记录；取消与既有CAS/原生清理规则仍执行。

library.exports 为唯一browser下的闭合只读动作，提供作品分组、版本分页、某版本采用素材分页、某素材/来源被采用的版本分页；每页最多20项，按页核对输出/素材当前指纹并区分缺失、变化和旧未知。跨Project仅返回摘要/身份/区间，不绕过复制后读取原文/媒体的门禁。GUI成品可查看版本和采用，素材可反查成品；参考/计划使用与实际采用保持独立。新增记录不能由模型或普通GUI提交。

实施顺序：账本契约与安全存储 → 合成快照及区间提取 → Studio/直接合成自动提交 → 素材库查询/成品分类/版本界面 → 故障与兼容回归。验收覆盖多次导出/缓存复用/超过草稿窗口、变速/分段旁白/末帧停留/静音与隐藏、跨Project复制、旧记录零写回、缺失或变化的文件、损坏/链接/取消/CAS，以及隔离原生导出与双向查询。

## 第三阶段实施细化

权威数据使用 Project 内不可变、按提交序号分片的单记录/小批量提交文件；每个文件限制4MiB，每千次提交一个目录。序号文件原子不覆盖发布即提交点，文件含Project/命名空间、前序SHA、稳定实体key和闭合版本化内容。取消在发布前回滚本次临时文件；发布后不会因派生索引失败撤销已保存证据。旧sources/catalog.json保留为只读基底，不重写旧来源、新闻批次、草稿或作品；基底指纹变化时拒绝混用。新来源获取以独立记录保存，同一来源不再堆积到一个数组文件。

SQLite仅为Host选定目录内的可删除派生索引，使用内置node:sqlite，不暴露SQL、路径或新模型工具。增量应用提交，事务内同步实体版本、检索文本和精确过滤词；损坏或缺失需在新一代索引文件中按有界批次重建，保留原损坏文件。查询核对索引检查点与权威提交SHA；索引落后、重建中、检索不完整均显式报告。只读跨Project浏览不创建目录或修复索引。原文全文由SHA核对后的已存文件构建，不触发联网或ASR。

稳定分页固定基底指纹、提交revision、过滤/排序条件和上一实体key；新采集与后续改写不挤入已有分页，刷新才看到新增。每页最多50项，索引扫描与读字节有界，允许无匹配但仍有后续游标，不冒充全库无结果。旧offset入口继续兼容，有游标入口用于长期流。来源定点读取/媒体关联/制作校验转为身份索引查询，避免每个操作读取全库。

事件容量层保存经过现有新闻证据核验的独立观察记录，绑定原Project/Session/批次/候选和来源身份；历史批次不迁移改写，按需只读兼容/显式同步。该层保留不同批次观察，尚不实施语义归并、自动热点判定或长期调度。多方向以稳定主题/方向身份过滤，不以AI新闻专用十条上限限制底层记录。

顺序为：安全分片提交与索引基础 → 来源独立获取及旧基底兼容 → 事件观察沉淀及分页 → 素材库/Studio定点读取适配与维护入口 → 超旧容量、崩溃/取消、损坏/重建、稳定分页和现有制作回归。原生回归继续只使用隔离Profile和模拟服务。

## 第四阶段实施细化

## 第六阶段实施设计

周期采集采用独立的 Profile 调度账本，不改写普通计划任务或旧新闻记录。用户在素材库显式建立方向计划，固定 collection Project、BMW Session、官方 driver 和来源订阅；新建方向或订阅不会自动启用计划。每个方向每轮有界遍历所选订阅，共享全局串行准入，来源仍使用既有十分钟/20次观察租约和证据游标。

调度使用固定的 Project/Session/driver，在独立隐藏页采集已激活或未激活的绑定，不自动切换用户工作区或重绑；不可用绑定保留一个待执行轮次并显示等待原因。忙碌、Project 过渡、制作/浏览器工作及隔离资源期间让行，空闲后继续。官方 Host 增加低优先级输入准入：用户输入到来即取消该后台输入，用户输入仍按 FIFO 等待真实清理；清理失败保留隔离。调度器不拥有模型循环，不调用额外工具，不自动制作或发布。

持久化顺序为计划轮次及确定的采集 ID → rolling uncertain 收据 → Host 输入收据 → 实际官方投递。每次重启只恢复一个合并后的到期轮次，不按停机时长补齐历史次数。未进入投递的待执行项可恢复；已投递项核对原 Host 收据及真实清理状态，未知投递或缺失回执进入待人工核对，绝不自动重发。成功收据不能代替采集证据；仅 rolling 完整检查可推进来源游标。终止与租约过期必须等待对应 run 的实际清理，不能误取消同 Session 后来的用户输入。

已确认失败/部分/受限按连续失败次数指数退避，最短5分钟、最长24小时，固定有界抖动；成功重置退避。每个方向保存当前轮次/待执行来源、下次时间、连续失败数、最后结果和等待原因；历史证据与 run 保留在原 rolling 分片。健康通知持久化、同状态去重，支持关闭系统提示及标记已读，恢复成功才发恢复提示；常规无新增不重复打扰。损坏账本保留原件并停用调度。

实施顺序：闭合调度/回执契约与原子存储 → Host 低优先级准入及定点回执/清理端口 → 公平调度、恢复/退避/健康通知 → 可信 GUI 配置和核对恢复 → 假时钟/重启/多方向/优先级/真实清理与旧选题制作回归。仅隔离 Profile 与官方运行时夹具验证，不推断在线社媒、付费模型或生产 Profile 覆盖。

### AI 新闻固定来源与真实链路验证

在现有六阶段基础上，增加可选固定来源目录：机构公告/研究、科技报道、中文媒体、X原创账号/主题/趋势入口和YouTube官方频道/主题入口。目录包含身份核对入口、范围与使用限制，不把预设当实时认证；可信用户选择添加，默认暂停、可关联当前Project方向，稳定预设身份保证重复添加保留已有修改，不创建周期计划或改写旧订阅。Agent仅可读目录，不能添加/启用订阅。

社媒观察区分账号、帖子、视频、主题和趋势入口，校验URL与平台身份；指标只能引用已存原文，未见指标保持缺失，不推算增长或全站热度。观察地区/语言明确为订阅配置范围，实际页面口径以原文为准；登录、反机器人、错误页不能成为完整成功检查，不推进游标。旧线索格式继续读取，新增观察类型为可选字段。

真实验证使用独立Profile/Project和公开原站Chromium页面，不复制登录态，不调用付费模型，不伪造页面、发布时间、来源署名或预览。按有限入口发现与文章核对、原文入库、线索、用户编辑事件、真实页面预览、候选核验、冻结推荐的顺序验证；本轮用户明确选择只验证近72小时；不足明确原因，不生成七天快照，不放宽旧news规则。若受限或合格独立事件不足十个，保留真实不足快照，不用重复事件、旧闻改日期或夹具补齐；离线严格十题与旧制作回归独立验证，结果不混称线上成功。保留在线证据、访问失败与来源状态、完整可复现报告。

实施顺序：固定目录与闭合订阅操作 → 可信GUI选择/重复保全 → 社媒观察类型与受限检查 → 真实来源验证与实际缺口修复 → 完整离线及相关原生回归、规范与验证说明。调度的用户优先、明确绑定、未知输入不重投和清理隔离保持不变；本工作不自动选题、制作或发布。

真实验证边界补充：原站只显示日期而无时区时，沿用现有最保守日期范围判断72小时；窗口滚动过程中已合格事件可能自然过期。不通过补造时区、改日期或放宽窗口挽留候选；保留旧完整快照及新不足快照，再对具体新文章进行有界补查。验证脚本每来源最多18篇文章，加入口及一次已知正文变化后的新获取共不超过20次原文观察；旧获取保留，不重投Host输入；空白社媒页面只等待有限DOM就绪，不自动重新投递输入。
