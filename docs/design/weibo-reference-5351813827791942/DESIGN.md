# BMW 竖屏科技资讯视频制作设计方案

设计日期：2026-10-08。状态：第一版提案，未修改应用实现。

后续方向已收敛为简洁卡片模板体系，见 [当前模板设计](TEMPLATE_SYSTEM_DESIGN.md)。本文件保留初步参考分析；依赖独立图层/音轨的实现建议由新方案替代，更细抽样分类以 [每秒两帧调研](DENSE_RESEARCH.md) 与 [设计增量](DENSE_DESIGN.md) 为准。

BMW 已能完成这类视频的素材采集、有限分镜、旁白、字幕、分层合成和 MP4 导出。建议先增加一个受限的竖屏资讯版式，并改善连续旁白和字幕制作流程，再考虑完整参考视频分析。无需引入另一套视频引擎、通用 HTML 导入或新模型工具。

## 视频的制作结构

画幅是竖屏，但核心素材大多放在中央近方形窗口内。顶部长期显示三行新闻标题，上方留有品牌区；字幕位于素材窗口下方，底部保留较大深灰空间。主体截图、短片和图解切换，整体框架保持一致。这是固定栏目包装下的素材叙事，不需要通用复杂剪辑器才能实现。

| 定位区间或抽样点 | 实际画面观察 | BMW 对应制作方式 |
|---|---|---|
| 开头约 0–2 秒 | OpenAI 标志、光环、飞散纸张的动态片段 | 导入已有短片；本地重建粒子或生成同类视频属于另外的素材生产需求 |
| 约 3–5 秒 | 文档背景，大字从“7”变化为“722篇”，随后变淡 | 数字文字对象或预渲染图片序列；精确计数曲线需更密集采样确认 |
| 约 6–9 秒 | 数学文档截图，截取区域变化，字幕推进 | 截图裁切、聚焦、画面片段与句级字幕 |
| 约 16 秒 | 阅读文档的人物片段 | 导入短片并统一框架、时长与颜色 |
| 约 24、32 秒 | 官方文档、中文说明截图 | 浏览器取材，保留来源；关键段落先用图像标注生成 PNG |
| 约 40–58 秒 | π、分数近似、数学对比图解，期间也穿插文档截图 | 原生图像绘制，或导入可验证图解图片 |
| 约 64、80、96 秒 | 社交帖子、长文及讨论截图 | 截图与有限焦点，不把参考视频截图当新闻事实证据 |
| 约 72、88 秒 | 工业设备、数学主题动态素材 | Project 短视频素材；不必为了它们新增生成服务 |
| 约 116 秒 | 文档页面叠加人物和姓名 | 截图主画面＋人物和姓名；简洁版使用固定人物模板或预合成素材 |
| 约 120、128 秒 | 文章/论文截图与结尾字幕 | 同一栏目版式延续到结尾 |

参考中的品牌标志和 AI 生成声明属于原作者包装。BMW 制作应使用自己的品牌与素材来源，不能默认把参考作者标志复制到新作品，也不能仅凭本地剪辑自动宣称作品由 AI 生成。

## 当前能力与缺口

能力判断以当前工作区的 [功能说明书](../../FUNCTIONAL_SPEC.md) 和 TypeScript 源码为准；工作区已有未提交修改，本提案不覆盖它们。

| 能力 | 当前实现 | 本次建议 |
|---|---|---|
| 竖屏输出 | 支持 9:16、720p/1080p、12–30fps，H.264/AAC | 直接复用；默认样片 720×1280、30fps |
| 视频长度 | 最多 180 秒，24 镜头，每镜头 1–60 秒 | 132 秒在预算内；实际分镜超 24 时，先用镜头内 visualSegments 表达，不能先假定已足够 |
| 网页取材 | page.media、media.download、截图、实播采集、来源记录 | 复用；下载受登录/地址可用性影响，实播采集必须报告截断 |
| 参考分析 | 每份最多八帧，最多八份记录，哈希与实际时间，Agent 分析 | 足以做初步风格分析；没有完整节奏、音轨或镜头自动分析 |
| 图片与图解 | image.draw/annotate 支持有界绘图、文字与标注 | 截图重点框、基础数学图解先做静态 PNG，不必新增动态矢量系统 |
| 独立对象 | 文字、矩形、图片、视频；位置/尺寸/透明度关键帧 | 复用人物、logo、大字叠加；每容器八视觉对象、全片六十四独立对象，四并发视频覆盖解码器 |
| 栏目版式 | 固定标题/素材/字幕模板；fullscreen 仍为模板内大窗口 | 核心差距：提供不绘制默认模板家具的受限资讯布局 |
| 文字排版 | 独立文字为固定字体、600 字重、左对齐；字幕已有对齐/描边 | 增加少量文字样式字段，或首版使用预绘制 PNG；不要增加任意字体路径/CSS |
| 旁白 | Edge/本地 TTS、真实文件、voiceTiming/voiceSegments | 复用；让资讯预设显式控制播放时钟，避免逐镜头默认留白积累 |
| 字幕 | 显式 cue、句级人工/Agent 校正、ASR 候选、双语、SRT/VTT | 复用；句级核对即可，不把估算 cue 或 BPE token 当词级对齐 |
| 配乐与原声 | 独立音轨、源区间、音量、淡入淡出、旁白避让 | 导入配乐即可；参考音轨未核听，不据此提出音频引擎改造 |
| 特效与复杂素材 | 有限色彩/模糊、淡变、聚焦；无专用 AI 图/视频生成流程 | 首版导入已生成/已有短片；粒子、复杂三维、任意 HTML 不进入本次范围 |
| 编辑与恢复 | Project/Session owner、CAS、撤销、来源与版本校验 | 所有新增能力继续复用，后台不得覆盖 GUI 编辑 |

## 第一阶段设计

### 固定资讯版式

在 media-native 的结构化合成契约增加一个可选、封闭的布局选择，例如 `frameLayout: 'news-portrait'`，并在 feature-video 保存与编辑同一参数。这里只是字段提议，需在实施时决定放在输出设置还是草稿合成投影，不同时维护两份。

建议首版仅支持 9:16，其他画幅明确拒绝该布局。旧草稿不含此参数时绘制保持原样。现有 fullscreen 含义不变，以免已有成片布局变化。

720×1280 的起始布局建议如下，位置是设计参数而非对参考逐像素测量：

- 背景：深灰纯色或一个 Project 静态背景图片。
- 品牌区：顶部约 40–110px，使用自己的透明 PNG 或文字。
- 固定标题区：约 y=140–280px，最多三行，居中粗体，固定全片标题。
- 素材窗口：约 x=40、y=360、宽高 640px，以 contain 为默认；允许有界 crop/focus。
- 字幕区：约 y=1040–1140px，白字加黑描边，最多两行。

标题和背景不因镜头切换重新入场；镜头标题用于组织内容，资讯布局不重复绘制它。预览、编码和关键帧使用同一 Canvas 绘制函数。定义固定绘制顺序：背景、素材、独立对象、栏目标题/品牌、字幕；重要文字的保留区纳入审片提示。

可先用已有全片图片层表示标题与品牌，得到可编辑参数较少的样片；正式版再以布局契约处理固定标题，避免靠遮盖原模板才能拼出画面。不要让新的模板在每个镜头重复创建相同标题对象。

### 连续旁白与字幕

以内容段落创建约 12–20 个镜头作为初始规划，镜头内可使用多画面片段；这不是已统计出的原片镜头数。先得到实际旁白音频，再计算各镜头时长。资讯预设显式设置 voiceTiming，从 0 秒播放或保留约 0.1 秒入场，而非默认每段从 0.5 秒起播再追加留白。

首版仍逐段生成旁白和人工试听，复用现有语音文件、绑定与作业机制。若试听发现拼接不自然，再加入“全段旁白导入/生成后按核对句区间分配”的宿主操作：同一音频 Artifact 被多个镜头引用，保留原文件秒数与哈希，不复制或伪造各段音频测量。先验证跨镜头解码与端点声音，再把它作为体验功能。

字幕优先使用核对后的句级锚点。原素材里的字幕若已烧录，应选择去用另一个素材版本或不叠加同内容字幕；不能承诺自动去字。换脚本会使旁白待更新，换音频会使锚点过期，沿用当前显式处理流程。

### 文字与强调

首版大数字、公式、斜贴纸、复杂装饰使用 image.draw 输出或外部导入 PNG，人物抠图导入透明 PNG。位移、缩放、淡入淡出使用既有 keyframes，重点标注使用 annotate。此方式可验证制作效果而不用扩展执行边界。

随后若需要直接编辑大字，给 VisualLayer.text 增加封闭的 `align`、`weight`、`outline` 样式，只允许固定枚举、颜色和数值上限；不增加任意字体名、字体文件路径、表达式或富 HTML。连续数字计数不是既有几何关键帧能力：首版用少量时序文字/图片；将来可加有界整数计数对象，但先确认实际需求及对象预算。旋转、粒子、三维不作为首版门槛。

### 用户流程

用户在现有参考素材预览中分析视频，将采样观察加入制作背景；在原 Assistant 输入说明主题和目标受众。Assistant 先给出脚本、素材需求与来源，再创建同一 Session 的草稿。用户确认脚本后生成旁白、补齐素材、核对字幕，最后查看样片并导出。

新增控件限于视频设置的资讯版式选择、固定标题/品牌，以及已有旁白面板的连续节奏预设。卡片继续编辑脚本和画面配对；复杂对象沿现有高级编辑入口操作，不增加新工作区、新聊天框或常驻流程按钮。

## 第二阶段参考分析

如果目标是“给一个视频链接，自动输出可编辑的同类作品”，需增加有限的完整参考分析流程，而不仅是版式：

1. 现有浏览器媒体发现/下载把原视频登记为 Project Artifact，记录来源与实测轨道；不能从微博页面 URL 直接当作视频 URL 下载。
2. media-native 按区间抽帧并生成有界画面变化候选；只报告像素变化，区分真实切换与滚动/推近，不自行声称语义镜头边界。
3. 音频进入现有固定 ASR 候选和试听校正流程。字幕 OCR 如需新增，使用固定运行时、语言和预算，并标为候选，烧录字幕不能自动当作正确转写。
4. 官方 Agent 根据真实帧、时间和候选生成分段观察。Host 保存受限结构及来源，不运行自己的模型循环。
5. 输出为可预览的制作建议：全片布局、段落时长、画面类型、素材清单与已有能力映射。用户明确应用后，通过 CAS 更新草稿；不自动覆盖脚本或重新配音。

现有 referenceRecords 的八帧格式保持兼容。完整分析宜独立为宿主证据记录，分页/分区向 Agent 提供，不能简单把八帧上限大幅放宽造成图像和上下文预算失控。采样质量、音频核对和语义观察分别标识，分析不赋予新闻事实核查状态。

## 模块与边界

| 模块/源码入口 | 预计改动 |
|---|---|
| media-native/composition-contract.ts、video-options.ts | 封闭资讯版式参数、合法画幅与字段验证、旧数据默认 |
| media-native/media/composition-paint.ts | 资讯版式、固定标题、不绘制原模板家具、字幕安全区 |
| media-native/composition-layers.ts、media/composition-layers-paint.ts | 可选有限文字样式；既有层、关键帧和解码预算继续使用 |
| feature-video/studio-contract.ts、studio-schema.ts、video-document.ts | 草稿字段、校验、合成投影和内容签名；具体入口实施前再次核对 |
| feature-video/renderer 现有设置与旁白编辑器 | 版式选择、固定标题、节奏预设、保存冲突与 Undo |
| feature-video/studio-reference.ts、studio-reference-contract.ts | 第二阶段的证据关联与建议，不篡改现有有限采样记录 |
| browser-capability | 只有确需新动作时扩展有效 browser catalog；不新增 MCP tool |
| harness-dsh/codex/qoder、Agent Host | 无需新增模型循环或供应商视频 API |

实现必须保留 Project/Session 归属、revision/CAS、FIFO、Project 切换排除、图像准入、输入回执、unknown 不重放。取消等待实际 Worker/工具清理，失败清理隔离资源。模型只使用 browser 和 Artifact ID；不开放 shell、宿主路径、cookies、凭据、Electron IPC、FFmpeg 或任意渲染代码。

本次用本机 FFmpeg 抽帧是开发分析手段，不是给 BMW Agent 增加 FFmpeg 能力。BMW 正式抽帧/绘制/编码继续采用现有 Mediabunny、WebCodecs、Canvas、WebAudio 与受限宿主 adapter。

## 落地与验收

建议实施顺序：先做 15–25 秒样片（固定标题、两个截图、一段动态素材、大数字、句级字幕、品牌），确认版式和声音节奏；再制作约 132 秒完整稿，验证预算、连续播放、字幕阅读与导出；最后按实际制作痛点决定是否加入完整参考分析、文字样式或生成素材服务。无需先实现第二阶段才能制作同类资讯视频。

验收包括：

- 9:16 的 720p/1080p 预览、关键帧和 MP4 位置一致；三行标题、长中文和字幕不静默截断；旧草稿保持原布局。
- 连续旁白开头、中段和尾段试听；时长以实际文件/播放范围为准，无默认留白累积，无引用过期时静默导出。
- 分割/修剪/调序后素材、旁白、字幕及固定栏目包装保持正确；背景与标题不在切点重新入场。
- 24 镜头/八层/六十四对象及视频解码预算内成功，超限明确失败，不靠放宽预算绕过。
- GUI 待输入期间后台结果不覆盖；CAS 冲突、取消、切换与清理失败继续保护原草稿、旧媒体和成片。
- 运行 build、check、unit、boundaries；运行相关 desktop、Studio、media、video、narration 及 DSH 检查。构建清理命令顺序执行，所有运行检查使用 disposable Profile。新增/移动测试运行 docs:features。
- 实施后更新 FUNCTIONAL_SPEC 的实际能力、schema 和权限；付费 Agent、在线 TTS 或外部生成服务另行实测，不从离线测试推断通过。

本次交付仅为下载、抽样视觉分析和设计，未运行应用构建或测试，也未证明原片完整复刻、声音匹配或三驱动实际制作覆盖。
