# 原始参考视频：每秒两帧复核

日期：2026-10-09。输入仍为原始 `reference.mp4`，不是 BMW 博客样片。本轮更新调研与设计，不修改应用能力。

## 抽样与证据

源视频、抽帧和联系表保存在本地研究目录，不纳入 GitHub 代码提交；仓库保留来源哈希、PTS 清单、复核记录与可重跑脚本。下文图像链接在持有本地研究素材的工作区可用。

- 原文件 SHA-256：`f676a8b05e5d47c7d473379864a5a01d7c0409feaadc3ba319a965857a2b674a`，与首次下载一致。
- 视频轨道 30fps、3964 帧、132.133333 秒；容器含音频，时长 132.190998 秒。
- 取原始解码帧 0、15、30……，实际 PTS 经 ffprobe 核对为 0、0.5、1……132 秒；共 **265 张 720×1280 JPEG**，没有插帧。
- [完整清单](dense-2fps/manifest.json)、[全部联系表](dense-2fps/index.html)、[可重跑抽样脚本](sample-reference.ts)。14 张联系表中的全部 265 个样本已视觉检查，并对关键细节查看原尺寸帧。
- 0.5 秒粒度可约束变化出现的区间，不能证明精确切点、动效曲线、逐字时钟或所有短于 0.5 秒的事件。本轮未整段核听、转写、OCR 或核查新闻/数学结论。

抽样脚本调用本机 FFmpeg 是开发调研手段，不属于 BMW 模型能力；不改变唯一 browser、八帧动作预算或 Project 参考记录契约。

## 对上一轮判断的修正

1. “截图加聚焦”描述过粗：需要把 **取景、原句强调、译文、人物身份** 分开，并规定它们怎样共同组成固定模板。
2. 图解不能只考虑“逐节点出现”：此片更明确展示了整图取景、共同目标与范围关系。先做好总览/细节，收益高于通用矢量动画。
3. 词句强调不应都塞进数字类。大字可以是数量，也可以是关键词；二者的数据字段不同。
4. 画面片段变化常比旁白段落更密。沿用镜头内多画面机制，不能每切一张图就生成一次旁白、重新留白或消耗一张顶层卡。
5. 仍没有充分证据支持连续鼠标轨迹、真实网页操作链、逐字声学同步或原片制作软件；它们不作为本轮复刻所必需的新功能。
