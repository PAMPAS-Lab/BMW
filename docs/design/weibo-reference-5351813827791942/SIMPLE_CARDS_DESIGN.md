# BMW 简洁卡片版竖屏资讯制作设计

日期：2026-10-08。状态：待讨论的设计提案，未修改应用代码。本方案替代上一版依赖全片图层和高级编辑的实现路径；参考下载与抽样依据见 [原分析](DESIGN.md)。

当前范围已扩展为八类卡片与共享动效，见 [模板体系设计](TEMPLATE_SYSTEM_DESIGN.md)。本文保留两类资讯卡的早期讨论，其中字段与实施范围以当前方案为准。

建议把参考视频拆成“全片栏目包装＋顺序内容卡片”，让用户始终在简洁卡片版完成脚本、画面、声音与字幕编辑。首版支持素材卡和数字强调卡两种资讯卡，人物叠加与复杂动画作为已合成素材导入。这里的目标是制作同类资讯视频；逐像素、逐帧、同音色复刻需要另外取舍。

## 为什么需要调整上一版

当前 [studio-compatibility.ts](../../../packages/feature-video/src/studio-compatibility.ts) 的 `simple.cards/1` 对任何独立视觉图层、自由关键帧和独立音轨都返回不兼容。服务写入和高级返回简洁模式均校验这个条件，不只是界面隐藏控件。

所以，不能在背后创建标题图层、人物图层、配乐音轨，再把草稿称为简洁卡片。方案采用明确、有限的模板字段，由共享绘制器直接绘制。原来的独立对象限制继续保留；扩展后通过真实内容推导简洁编辑资格，不接受客户端提供“简洁兼容”证明。

另一个实际问题是 [studio-service.ts](../../../packages/feature-video/src/studio-service.ts) 的生成旁白流程会清除 voiceTiming/voiceSegments，再按默认留白重算时长。仅在 UI 中改一次时间不能形成持久的紧凑制作流程，需要让宿主生成和导入音频也理解节奏设置。

## 产品结构

| 层级 | 用户编辑内容 | 表达方式 |
|---|---|---|
| 全片 | 竖屏资讯版式、固定栏目标题、品牌、旁白节奏、字幕预设、现有配乐开关 | 原视频设置中的有限参数，只保存一份 |
| 一张卡片 | 段落名称、旁白脚本、卡片类型、画面素材；数字卡还含数字和单位 | 原 canonical scene，不新增脚本或卡片副本 |
| 卡片详情 | 素材片段列表、有限取景、旁白试听和句级字幕 | 原“换画面”“声音与字幕”详情入口，无自由时间轴 |

一张卡片对应一个内容段落，不必对应每次画面切换。一个段落可以顺序播放多张截图或短片，复用现有每镜头最多八个 visualSegments。卡片之间决定叙事顺序，卡片内的短素材列表决定配图顺序。

## 用户看到的操作

顶部沿用视频名称、保存状态、撤销/重做、目标与素材、视图切换和交付入口。视频设置仍从原“更多”进入，加入“竖屏资讯”版式选择。第一次选择时在同一设置中填写栏目标题；不为此增加独立工作区或常驻按钮。

卡片仍保留“编辑卡片”“换画面”“声音与字幕”三项入口：

- **编辑卡片**：在现有版式选择器中展示“资讯素材”“数字强调”；数字强调选中后只出现数字、单位和显示方式。卡片列表名称仍是原 scene.title，用于组织段落，不在资讯成片上重复绘制。
- **换画面**：选择 Project 图片或短片；多画面时展开短素材列表，显示顺序与各段时长，提供追加、替换、调序和删除。默认等分时间，用户可改秒数；超出镜头、源素材或八段限制时保留输入并报错。删除镜头不删除 Project 源素材。
- **声音与字幕**：编辑脚本/试听、生成旁白、查看 ASR 候选、核对句级字幕；紧凑节奏默认来自全片设置，不重复在每张卡片展示一排高级字段。

卡片拖动继续只改变顺序；“让 Assistant 改这一镜”沿用精确所属 Session、sceneId 和 revision。多画面或有限聚焦本身并未被当前 simple.cards/1 拒绝，但现在卡片会显示“含高级编辑”入口；新增简洁素材列表后，需要把提示改成“多画面 · n 段/取景已设置”，直接打开原卡片详情。真正的独立图层/音轨仍按现有不兼容规则处理。

预览中的栏目标题是全片内容：点击时打开全片设置，不把它保存到当前 scene.title。数字卡的数字和单位可通过既有“编辑卡片”修改；画布直接编辑数字是后续增强，不作为首版必要条件。当前标题/要点的直接编辑命中区域不能误指向资讯布局中未绘制的旧模板标题。

## 全片版式

首版只支持 9:16，720×1280 或 1080×1920，沿用现有帧率和 MP4 编码。采用固定深灰背景、最多三行居中标题、近方形素材窗口、下方最多两行字幕；参考底部留白保留为版式空间。位置由模板规定，用户无须拖框。

建议保存一个可选 `newsLayout` 配置：enabled 开关、固定 kind、headline、可选 logoArtifactId。字段名为设计提议。headline 不复用作品文件名或每段 scene.title，最多 80 个 UTF-16 单位且须通过真实三行排版校验；logo 仅引用当前 Project 静态图片，使用固定品牌区。没有配置或未启用的旧草稿完全沿原绘制路径；关闭后仍可保留配置内容。

共享绘制顺序：固定背景 → 当前素材与取景 → 本卡数字强调 → 全片栏目标题/品牌 → 当前字幕。模板内的默认 label、镜头标题、镜头编号和底部进度条不绘制，原字段仍保留供卡片组织和其他版式使用。标题与品牌跨镜头保持，不重复入场。字幕区域由该版式定义，复用现有颜色/描边参数；设置与审片均须按实际区域检查，不能只沿用原模板的基线常量。

选择资讯版式时不自动缩短标题或改写旧字幕。已有不适用 sceneTemplate 的草稿先显示需要处理的卡片及预览，用户明确应用替换才更改；不通过后台切版静默删掉要点。切回旧版式保留资讯配置供再次选择，但不把不支持的数字内容悄悄隐藏：提示先转换成普通素材或保留资讯版式。

## 两种资讯卡

### 资讯素材卡

用图片或短片讲述一个段落，支持卡片内顺序片段、既有有限 crop/focus、cut/fade。关键段落标注和数学图解使用当前 image.annotate/draw 生成新的 PNG，再放进该卡；原图保留。动态主体素材可从网页取材或导入现成短片。

资讯素材卡没有自由叠加对象。人物与文档同屏如需首版支持，就准备一张已经合成的图片或短片作为主画面；在卡片里仍能换图、调时长、配音与改字幕，但不能独立移动其中人物。

### 数字强调卡

在主素材窗口的固定中心位置绘制一个数字和短单位，例如“722 篇”。这是受限卡片模板，不映射为隐藏的独立 layer，也不开放坐标、zIndex、关键帧或表达式。

建议可选 `newsMetric` 字段包含一个 0–999999999 的整数、最多八个字的单位、`static` 或 `count-up` 两种显示方式。首版无小数、负数、多个数字或任意格式字符串；可以直接选 static，避免为模仿参考中尚未精测的数字效果过度开发。无背景素材时使用模板底色，制作检查将有效数字视为真实画面内容，不能继续按“没有素材/要点”误报缺画面。

count-up 如纳入首版，使用固定约 0.6 秒的整数递增，再保持终值，按给定播放时间纯计算，无计时器状态。它只能证明 BMW 的设计效果，不代表与原片逐帧一致。镜头分割必须复用已有 presentationWindow 原始时钟，续段不能从零重新计数；调整播放时间不能改变数值内容。没有来源时钟的复杂变化需明确重设，不能补造原始身份。

保持同一份数字内容，预览、关键帧、导出和卡片编辑共同消费。文字测量、最小字号、单位换行和超框校验也必须共享，不能预览一套、编码另一套。

## 紧凑旁白节奏

新增 `standard` 与 `compact` 两个全片节奏选择，旧草稿默认 standard。compact 对新生成或新导入的单段旁白，按实际音频长度建立显式 voiceTiming，并在两端各留约两帧。例如 30fps 时前后各约 0.067 秒；最终镜头时长向帧网格取整。它减少 BMW 模板留白，不删除音频文件自身的静音。

生成/导入服务、narrationSceneDuration、句锚点投影、估算字幕、制作检查、预览及导出必须消费同一时钟。旁白文件的实测长度保持不变，不能用播放片段长度替代音频测量。脚本修改沿原规则使旧音频过期；估算字幕继续标估算，ASR 继续是候选。

选择 compact 只控制后续新旁白。已有镜头提供明确“应用紧凑节奏”操作，先显示可调整卡片和将保留的卡片；仅对可安全重算的单段时间应用。人工字幕终点、源素材覆盖及焦点须通过校验，不能强行缩短。已有分割来源、人工剪切旁白或 voiceSegments 不做首版批量重排，保留原播放区间并说明原因。

段与段之间仍可能有 TTS 音色/语气不自然的问题，紧凑时间不等于无缝声学拼接。首版通过同一声音/速度及试听处理；整段合成后按核对句区间分配，可作为下一阶段，但会影响多卡片音频版本、句锚点和局部重做，不宜顺便加入。

## 需要一起决定的取舍

| 参考效果或需求 | 简洁首版建议 | 不能完整满足的原因 | 想进一步支持时的选择 |
|---|---|---|---|
| 固定标题、深灰背景、中心素材、底部字幕 | 支持 | 需要新的共享模板与校验，当前固定模板位置不同 | 首版核心 |
| 开头三维光环、飞散纸张等短片 | 可导入与播放 | BMW 无该素材的生成/三维制作能力 | 首版使用现成素材；生成服务单独设计 |
| 大数字强调 | 支持固定位置静态数字，递增效果可选 | 现有关键帧只控制几何/透明度，不控制数字值 | 首版增加受限数字模板；精确原片节奏留待精测 |
| 人物与文档同屏且人物可独立修改 | 导入合成图片/短片 | 人物独立图层违反现有简洁契约 | 如确需可编辑，增加仅一个人物槽和固定姓名槽的专用模板，禁止自由图层 |
| 截图重点框、公式/数学图解 | 静态 PNG，卡片可换图 | 动态箭头/公式逐步出现需要新的形状与时间契约 | 先用序列图片或预渲染短片；后续增加有限图解卡 |
| 全片自选 BGM、多音效 | 首版沿用现有原创配乐开关 | 独立音轨不兼容简洁模式；全片 music 当前是布尔值 | 若自选 BGM 必需，增加唯一结构化背景音乐槽并流式复用混音器；不保存为 audioTracks |
| 逐字高亮、与原音完全对齐 | 首版核对句级字幕 | 当前自动词/字时间未批准，BPE 不等于字词时标 | 保留句级；逐字功能需独立声学验收 |
| 一次导入链接自动复刻全片 | 首版辅助分析后生成卡片 | 现有参考仅八帧抽样，无全片节奏、音轨和语义分段分析 | 单独建设有界分析流程；先不成为制作前置门槛 |
| 任意拖动文字、多个浮层与复杂转场 | 首版不提供 | 会把卡片扩展为自由对象编辑器，参数和裁剪规则明显增加 | 个别高频效果用固定模板；其他用预合成素材 |
| 超 24 内容卡或超过 3 分钟 | 不放宽总预算 | 现有合成/文档/验证预算，不只是列表限制 | 多次画面切换合到一张段落卡，每卡最多八段；超时拆成多条视频 |

推荐首版：资讯素材卡＋固定数字强调卡＋栏目包装＋紧凑旁白＋句级字幕，复杂素材导入、配乐先用现有开关。人物可编辑槽、自选 BGM 和动态图解均为可追加范围，并非原则上无法在卡片模式实现；是否加入取决于实际制作频率与可接受的卡片参数量。

## 实现范围与兼容

| 入口 | 设计改动 |
|---|---|
| media-native 合成/输出契约与共享 Canvas 绘制器 | newsLayout、newsMetric、合法 9:16 画幅、实际文字区域、纯时间数字效果与模板资产准入 |
| feature-video studio-contract/schema、video-document 双向 codec | 草稿单份字段、有限模板资格、settings/story 投影、Schema 版本与 round-trip |
| studio-compatibility / video-edit / 服务能力描述 | 识别新的有限卡片，继续拒绝任意 layers/audioTracks；Agent 可验证实际支持的字段 |
| studio-service 与音频导入/生成路径 | compact 时钟、可安全应用范围、真实测量、CAS 原子保存与取消清理 |
| studio-cards / studio-card-text / 原设置、素材与声音详情 | 两种卡片选择、有限参数、顺序素材列表、固定标题编辑归属；保留三入口和原输入 |
| 制作检查、文字审片、签名/引用资产收集 | 数字无素材资格、标题与 logo 校验、布局/数字变化使旧成片失效；品牌文件变化不得复用旧输出 |

VideoDocument 当前是 bmw.video 2.0，新增字段必须同步 schema、双向 codec、能力描述和测试，不能只改渲染器。是否提升文档版本在实施前统一确定：若提升，采用明确版本检查与受限迁移操作；不在正常启动中自动改写旧 Profile。旧数据缺少可选字段时仍保留原行为；不靠扩大 any 或 typecheck 例外接受输入。

简洁能力 profile 建议提升到 `simple.cards/2`，明确声明有限资讯模板、画面片段与节奏能力。它与文件 schema 版本分别管理；不能继续宣称冻结的 simple.cards/1 已支持新字段，也不能让旧客户端把新数字卡解释成普通卡而漏掉画面内容。

新增品牌图片仍是 Project Artifact，要进入读取/解码/像素预算、前后哈希核对与取消释放；不得直接把路径给模型。newsLayout/newsMetric 均进入有效内容与导出签名，记录或默认值不得伪造旧成片已更新。模板的跨镜头标题、数字时钟与原播放证据分别处理，不把全片字段复制成每卡数据。

DSH/Codex/Qoder 仍由官方运行时拥有 Agent Loop。BMW 不引入新的模型工具；如目录新增受限 action/字段，继续通过唯一 browser 的验证目录发布。保持 Project/Session owner、expectedRevision、FIFO、Project 切换排除、输入回执与 unknown 不重放；取消等待实际工具/Worker 清理，失败清理继续隔离。

## 验证与阶段安排

先做约 20 秒、三张卡片的可审样片：动态素材卡、文档数字卡、截图解释卡，展示固定栏目标题、一次卡内换画面、紧凑旁白和句级字幕；全过程只用简洁模式。复杂动画素材的具体来源在制作时确定，不预先宣称生成效果可用。

设计通过后再实现，验证要同时覆盖：

- 新草稿只用有限参数，simpleEditable 始终为 true，持久草稿无隐藏 layers/audioTracks；既有高级草稿仍被拒绝。
- 栏目标题/数字/多画面可保存、重启恢复、撤销/重做、卡片调序；字幕和旁白仍是原字段，双向 codec 不丢失。
- 旧草稿预览/导出保持；9:16 两种分辨率、长标题/单位/字幕、logo 解码和预算、末帧、切点计数正确。
- 生成和导入音频真的执行 compact；人工字幕、已分割旁白及片段来源不会被批量节奏操作覆盖。
- 背景任务与 GUI 并发版本冲突保留用户输入，取消/清理失败保留旧媒体与草稿，源图片变化阻止错误成片复用。
- 卡片详情与预览在宽/窄窗口、键盘操作及真实 Electron View 下可用，无需进入高级编辑。

实施后按仓库要求顺序运行 build、check、unit、boundaries，并跑相关 desktop、Studio、media、video、narration、DSH 检查；新增/移动测试运行 docs:features。更新 FUNCTIONAL_SPEC 的已实现功能，不把本提案写成当前能力。所有运行检查使用 disposable Profile；付费模型与在线服务需独立覆盖。

本次交付为设计与交互示意，未实现上述新增字段，未运行应用构建/测试，也未完成原片整段音频或逐帧复刻验收。
