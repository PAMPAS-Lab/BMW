# 简洁卡片：密集复核后的设计增量

日期：2026-10-09。状态：本轮核心能力已实现并通过原生验收，OpenAI 博客样片已更新；基础模板保持兼容。[每秒两帧研究](DENSE_RESEARCH.md) 是本版证据依据。

## 设计决定

继续保持八个一级类别。新增 **证据阅读、原句重点、原文/译文、人物引述、背景数字、关键词强调** 六个变体；图解总览/细节采用共用取景配方，范围关系和多对象对同一目标也已接入。变体按所属类别展开，基础八个入口保持可见。

模型依然先选八类，再按表达需要选该类的一个变体。人先编辑内容，只有需要强调、译文或人物时才展开对应槽。变体提供新能力，配方只给现有字段建议，两者不能混为已经新增的执行能力。

## 新增模板与共用能力

| 建议模板/配方 | 依据 | 最少需要填写 | 建议边界 | 实施前差距（本轮已补齐核心能力） |
|---|---|---|---|---|
| **证据·阅读** `evidence/reading` | 22–27、77–89 秒 | 一个来源素材，最多三个阅读目标 | 整页→一处、局部→全貌、依次读两处；每目标包含停留 | 已有手工 focus；缺少配方、目标/时钟提示及少填参数的编辑 |
| **证据·原句重点** `evidence/highlight` | 11–13、63–67.5、81–89 秒 | 来源、最多三个重点、强调顺序 | 框线/底色/原句反白；一次只提供该素材可用样式 | annotate 可输出 PNG；简洁卡内可改重点、时序与换源失效尚未实现 |
| **证据·原文/译文** `evidence/translation` | 95.5–101.5 秒 | 原文依据、一段原句、可选译文、来源 | 译文独立解释槽，最多两段，不能直接改写源截图 | 原字幕已有双语；素材窗内部的原文/译文版式是新能力 |
| **证据·人物引述** `evidence/person-quote` | 113.5–121 秒 | 文档/引述、人物图、姓名；身份可选 | 一个人、一段引述、两个固定位置；译文可选 | 简洁模式暂无专属人物槽，现阶段只能预合成 |
| **数字·背景依据** `metric/backdrop` | 3.5–5.5 秒 | 原数值/单位/说明，可选一张背景及来源 | 大字居中、背景弱化；计数结束后可退回依据 | 当前 metric/hero 不保证背景语义；新增明确背景槽与退场/依据阶段 |
| **标题·关键词强调** `title/emphasis` | 11.5–13 秒 | 一个短词句，可选一张背景 | 大字淡入或整句擦入；可选保留背景重点 | 当前标题不能表达这种背景证据上的固定强调组合 |
| **图解·总览/细节**（取景配方） | 39.5–43 秒 | 一张图、一至三个目标 | 同证据阅读共用配方；明确局部与整图的停留 | 已有 focus 的复用和 GUI 简化；无需另做节点动画引擎 |
| **图解·共同目标** `diagram/to-target` | 41–44 秒 | 二至三个对象、一个目标、短关系标签 | 固定箭头与卡位；对象内容短，复杂公式先用图片 | 新固定关系模板；不是将三项内容塞进两项对比 |
| **图解·范围关系** `diagram/range` | 52–57 秒 | 轴的含义、目标位置、已达区域、条件说明 | 单轴、至多两个阈值、一个区域；数值/符号二选一 | 现有图片可承载；结构化阈值、比例与解释限制需新增契约 |

这些 ID 已通过闭合 CardSpec v2 契约接入 describe-template；八类摘要保持不变，新增内容要求文档 2.2。

证据的“阅读方式”是上述证据变体共用的有限配置，不要求另开一张阅读卡。基础阅读/重点版最多三个目标；译文或人物引述版先限一个原句目标，以免同时填满多个解释槽。第一步重点只接纳静态图片；长文分段可沿既有 visualSegments 展示不同图片，每张图片的目标必须归属自己的源。动态录屏中的重点仍走原 demo 的取景规则，不把静态图坐标长期贴到会滚动的视频上。

标题强调复用 scene.title；数值复用已有 numeric CardSpec；旁白、字幕、素材、来源、时钟继续采用原草稿字段。新增专用内容只放到该变体的闭合字段，不复制一份“模板正文”，也不做所有卡片通用的任意组件数组。

## 先补“证据怎样读”

证据类最常见流程改成：**选素材 → 选阅读方式 → 指出一至三处重点 → 填可选解释**。默认只需素材和说明，其他入口按需展开。

| 阅读方式 | 系统承担 | 人/模型承担 |
|---|---|---|
| 原画面 | contain、固定安全区 | 合适的源图和一句说明 |
| 整页到重点 | 有界过渡、停留和回到整页的可选结尾 | 一处源图范围 |
| 局部到全貌 | 先停在局部，再退到全图 | 一处局部范围 |
| 依次读两处 | 避免无意义长距离移动，必要时采用淡切 | 两处范围、先后关系 |

停留时间先由模板推荐，不让模型填写曲线；配方保存有限阅读目标，由共享原生绘制器安排建议停留和过渡；不写入第二份手工 focus。一个配方只占一种表现选择，不能继续叠加 slow-push、另一条 focus 和自由 keyframes。模板自动安排的时间标为建议/估算；新增配方当前采用建议/手工秒数；已有按句 focus 入口可继续使用，不将新配方宣称为自动句绑定。

### 重点、取景与文字的坐标关系

原句重点使用 **源素材坐标**，经同一 crop/focus/缩放变换进入素材窗；人物、身份、译文使用 **模板固定槽**。必须避免背景取景时人物一起被放大，或重点框留在旧屏幕位置。

- 一个逻辑重点可覆盖最多三行矩形，仍只算一个重点；全卡最多三个重点、九个矩形。模型不用伪造 OCR 字符位置。
- 图像标注可从鼠标框选产生；模型填写归一化源范围后仍要实际预览。固定像素上限、矩形总数和颜色枚举，不开放任意 path/CSS。
- 原句反白优先处理实际源像素，不能自动“黑框＋重新写一遍推测原句”。彩色/低对比源预览不可读时，提示改用框线或底色；已有烧录反白的图不再叠一遍。
- 每个重点保存源 Artifact/哈希与区域。换图、重截图或来源变更后失效并提示重新确认；不把旧框直接套用到新素材。
- 从 PNG 合成重点转成可编辑重点必须拿到未标注原图；没有原图时保留烘焙图，不承诺自动拆层。

## 原文、译文与人物：固定槽，不变成高级编辑

译文放在受控解释栏，默认不覆盖原句。原文/译文可切换“同时显示”或“先原文后译文”；后者最多两个阶段，使用整句显现，不承诺逐字对齐。底部字幕继续服务旁白，不能将字幕译文自动当成被引作者说过的内容。

原句最多 160 字符、译文最多 160 字符；长段需节选/分卡，禁止静默截断。原句与来源关联，译文标明为译文；没有可核对原句时可以写“解读”，不能伪装成直接引述。引用来源与叙述者关系要明确：作者、发言者、被介绍者不能只凭头像推断。

人物引述只有一个人物图、姓名（32 字符）、身份（64 字符）及一段引述。提供“右侧人物＋左侧证据”或“人物角标＋整页证据”两个固定变体。透明 PNG 与普通照片均可用，普通照片显示固定肖像框，不自动承诺抠图。若人物遮住重点，要求换固定位置或缩短内容，不能靠不断缩小字号解决。

右侧人物不建立隐藏独立 layer；它是新模板的专用槽。人物进出为静态/淡入，名字随人物共用阶段。不增加人物自由旋转、嘴型或运动轨迹。

## 数字和词句：从“只占一张卡”扩展到“附着于依据”

背景数字和关键词强调各只有一个可选背景，第一步限静态图；动态背景先用素材卡。保留原 numeric 的非负/精确小数限制；公式、区间、负数和分数不强行转换成 count-up。

“退回依据”是两个固定阶段：先读大字，再淡出大字看背景。背景停留是设计内容，不是把数字 opacity 设零就算完成。中途分割后使用原镜头表现时钟，不能在子段重新计数或重新入场；换模板必须展示背景、重点、译文或人物哪些将不再显示，并沿 CAS 一次保存，可撤销。

关键词默认复用标题，最多 20 字符；资料图保留来源。默认整个词句淡入，擦入可选且不绑定语音 token。不会为每个字建立一条对象或动画。

## 图解能力：先读图，再考虑可编辑结构

原片的两类图解分别表达“多个近似→一个目标”和“当前范围→尚未达到的目标”。它们不等于普通对比，也不只是画一个好看的坐标轴。

第一步采用已有图片＋阅读配方，模型只需要完整图和阅读目标。第二步才增加两种结构化图解，供内容适合固定关系时使用：

- 共同目标：对象二至三个，目标一个；每个对象一个短标签或图片，关系标签最多 24 字符。箭头由模板绘制，模型不填位置和曲线。
- 范围关系：数值模式要求实际数值、轴边界、单位与条件，严格检查顺序和范围；符号模式只展示符号关系，明确“示意/非比例”。没有真实数据，不生成看似精确的图表；复杂数学原图继续导入。

可选“逐项出现”只在结构化图解真正拥有节点时启用。整张图片无法独立编辑内部节点；预制动画也不能假称节点可编辑。通用 LaTeX、任意 SVG、完整图表系统和无限流程不进入本轮。

## 段落与画面片段

证据阅读与素材序列共享“一个旁白段落，多个有限画面”的组织方法，继续使用现有 visualSegments 和有界预算。用户不用复制旁白、字幕或来源；一个区间引用实际原素材，不重新下载一次。

建议段落配方新增：

| 表达任务 | 卡片/阶段顺序 | 避免 |
|---|---|---|
| 报告一个数量 | 背景数字 → 原文重点 → 条件解释 | 大数字脱离条件 |
| 解释一段外文观点 | 来源总览 → 原句重点 → 译文/人物引述 | 将编辑译文伪装成源截图文字 |
| 说明“进展仍有缺口” | 证据 → 图解范围 → 限定结论 | 用数值越大暗示结论成立 |
| 解释一个关系 | 图解局部 → 图解全貌 → 要点 | 无依据地生成复杂节点动画 |

配方仍只输出分镜建议，不新增运行对象。前期默认整句旁白，按实际音频时长安排片段；不因为画面多一次切换就追加一段 TTS 留白。

## 简洁卡片怎么编辑

八类入口不变。在“编辑卡片”内先显示此变体必要槽，再提供最多一个“阅读与重点”折叠区。译文和人物是所选变体的字段，不在每张卡上摆一排功能开关。

1. 证据卡打开后显示素材和说明；可切“阅读/重点/译文/人物引述”。切换前展示实际内容预览及变更影响。
2. 阅读方式默认原画面；需要强调才点“添加重点”，在同一个预览框选，卡内出现可重命名、删除和调序的重点列表。
3. 选人物引述才展示肖像、姓名、身份和引述；选译文才展示原句/译文，复用现有素材和来源选择。
4. 时序默认自动建议；详细秒数折叠，新增重点先提供手工秒数。自动跟随句锚点需增加引用失效与恢复契约，暂不在新配方上开放；已有按句 focus 保持。
5. 切回基础模板只关闭该变体表现，不删除 Project 文件；内容不能悄悄丢失，不能用隐藏 layers 保留已不支持内容。

模型只收到八类摘要；读取证据类详情时再看到四个表达任务。所有硬上限、槽及允许表现来自统一定义，GUI 与 browser 读同源契约，未实现模板保持不可用。

## 是否新增第九类

本轮不建议增加一级类别：原句强调/人物引用仍围绕证据，词句强调仍围绕标题，范围/共同目标仍围绕图解。新增“动效”“人物”“公式”“代码”会把素材、表现和表达任务混在一起。

可保留 **数据图表** 为独立类别候选，触发条件是以后需要反复制作柱/线/散点图，且存在可验证的数据表、轴、单位与自动刻度。它与本片的说明性数学图片不同；只有具备数据输入、领域校验、可编辑结构和相应验收后才新增。时间线也先作为图解变体，不根据本片虚构其已出现。

## 实施次序与验收

| 顺序 | 范围 | 为什么先做 | 主要验收 |
|---|---|---|---|
| A | 共用阅读配方＋可编辑证据重点 | 原片高频，提升多类现有图片能力 | 源坐标经过裁切/推拉后正确；换源失效；不覆盖旧人工取景；分割时钟连续 |
| B | 原文/译文＋人物引述 | 旧抽样漏掉的固定多槽表达 | 原句/译文/字幕分开；身份来源明确；人物不随背景取景；横竖安全区；无隐藏 layers |
| C | 背景数字＋关键词强调 | 有明确参考，可由少量专用槽完成 | 背景来源、两个阶段、精确数值、切割不重启、转换提示/撤销 |
| D | 共同目标＋范围关系 | 可编辑解释能力增量大，但语义校验成本也更大 | 符号/比例区分；数值轴条件；真实节点逐项出现；图像后备方案 |
| 延后 | 连续真实鼠标轨迹、复杂三维、通用代码/公式/矢量编辑 | 本片没有充分轨迹证据，其他项会明显扩张输入和运行边界 | 另行立项与真实来源证明，不借模板绕过权限 |

每批保留旧 2.0/2.1 内容行为，新增字段通过明确新版本条件发布，不能先承诺继续写 2.1。实现归 feature-video，绘制/编码归 media-native；统一预览/导出、内容签名、Project/Session、revision CAS、撤销、取消清理和资源预算保持。仅已验收模板进入有效唯一 browser 目录。

验收片不必逐像素复刻参考，但要实际包含：长文两处阅读及反白、原文/译文、人物引述、背景数字退回依据、关键词、图解局部/全貌；两种画幅实际导出，检查文本遮挡、原文件保全、后续分割与调序。用六个示例任务验证“模型只读当前模板，人只见必要槽”，不能以功能开关数或类别数代替认知成本验收。

## 实现取舍与交付位置

阅读配方直接保存受控目标和固定方式，保留原图坐标与原时钟，避免同时存在生成的 focus 和配方两个可编辑权威。停留由画面原时长平均安排，过渡最多 600 ms、取景缩放最多相对于基础裁切四倍；详细重点秒数可编辑。新配方不自动绑定句锚点，因为语音替换、分割及校正后需要额外处理引用失效，现有按句 focus 可继续使用。

缺少未标注原图不自动拆除烘焙标注。人物图使用项目静态图片选择器和固定框，不额外调用抠图服务。博客原文署名 OpenAI，样片不虚构个人讲话或个人头像；人物两种位置与范围关系在受控验收片中单独验证，不把速度报告伪装成进度比例。

代码：media-native 的 card-details / card-details-paint；feature-video 的 studio-card-details、卡片转换、文档 2.2 和源校验。验收与新版博客输出在 `.bmw-runtime/dense-card-validation`、`.bmw-runtime/card-blog-sample`；旧成片仍保留，修改前草稿与报告另存 before-dense 快照。

### 本轮验收结果

- 构建、类型/源策略、文档 Schema、功能清单、模块边界检查通过。unit/contract/boundary 分类运行 82 组通过；媒体、旁白、DSH、Desktop 与原生视频回归通过；Studio 最终补验 29 组全部通过。早期 Studio 的旧版本断言及保存/重载等待条件已修正，未将测试中途修改源码的报告当作完整成功报告。
- 新增变体实际导出 640×360、360×640 两种画幅，验证真实红色源图反白为青色、人物两个位置、共同目标及数值/符号范围。鼠标框选保存实际源 SHA，译文沿 CAS 保存，撤销/重做通过。
- 宿主分割后，原生绘制器在四个时点的阅读取景、数字计数与退场像素最大差均为 0；源文件变化拒绝消费并保留旧输出。
- 博客保持同一草稿和来源，现为 10 张卡片、约 56.4 秒、720×1280。实际导出的 40 张关键帧已复核，独立播放器已解码播放视频与音轨；不以此声称整段人工核听或自动词级同步。
- 最终路径、草稿、哈希及分层验收记录见 `.bmw-runtime/dense-card-validation/acceptance.json`。正式用户 Profile 和付费 Agent 未用于验收。
