# P1 / AK 本机记录分析

分析日期：2026-10-28。依据 `.bmw-runtime/p1-ak` 的日志、结果与已登记交付；此为历史证据梳理，不是对当前代码的重新测试。日志中测试故意触发的错误、Chromium 提示和业务失败需要按上下文区分；不将中间轮次的通过数相加。

## 主要发现与建议

1. **P1 — Studio 选择、保存与预览事务。** `final-all.log` 和 `source-span-regression.log` 曾出现选择旁白片段时播放头断言失败；`studio-admission-recheck.log`、`studio-redo-settled-recheck.log` 及 `studio-exact-conflict-recheck.log` 有属性选择或保存等待超时。历史 [验证说明](../VERIFICATION.md)记载：最初将问题归于并行窗口的推断被后续复现推翻；随后捕获操作前逻辑时间、串行选择/保存/预览并在预览准备期间禁用主轨控件。`studio-settled-selection-recheck.log` 和 `studio-timeline-admission-recheck.log` 后续记录主编辑事务及 Studio 通过。建议当前改动继续保持真实 GUI 中选择、保存、预览、CAS 与播放头一致性回归；这些历史失败本身不能证明现在仍存在。
2. **P1 — 用户编辑和 CAS 冲突。** `complete-all.log` 中旧模式切换冲突用例等待超时；历史修复记录说明应等待确切对象和选择/预览事务完成，并保留未保存输入及音轨 CAS 断言。不要通过放宽断言或直接覆盖草稿消除失败。
3. **P2 — 封面影响分析。** `cover-plan-unit-fixed.log` 中单元断言为 `rebuild` 而期望 `keep`；[验证说明](../VERIFICATION.md)记录后续补充 cover 候选与服务级检查，以及真实调用证明封面重建、视频和场景保持。建议对来源指纹、实际文件与 revision 持续做影响矩阵核验；不把旧日志命名中的 fixed 当成通过证据。
4. **P1 — 实际视觉/声音与验收分开。** P1/AK 涉及新闻、科普、学术和组合片；记录包括 Qoder 制作、导出、关键帧和音频。历史用户对不同新闻版本有不同反馈，最新版本的专项听感、复述和接受仍待确认；技术音轨、模型视觉审阅和 Agent 输出不代替人工核听。保留原声、字幕与来源身份及版本绑定。
5. **P2 — 图解与代理的真实性。** 原生图解及 16 格代理有实际 Canvas/MP4 验证；部分实验重复同一源的不同区域，六轮外部结果链是契约夹具，未调用外部生成服务。应明确区分真实生成、素材导入和夹具模拟。
6. **P2 — 中断与回执。** 历史工作包含 24 秒试片及 45 分钟中断；后续使用新明确输入只补缺失部分。恢复必须保留原 Session、draft、revision 和来源，未知投递不自动重放。

最终冻结历史报告记录 162 passed / 0 failed / 12 not-run；其范围、源码指纹及真实付费调用的区别见 [可移植交付](P1_AK_DELIVERY.json) 与 [验证说明](../VERIFICATION.md)。本次统计的 `native` 下 50 份 `result.json` 均含 `passed: true`，这不代表 50 项独立覆盖或当前版本通过。未重新运行测试或生产模型。
